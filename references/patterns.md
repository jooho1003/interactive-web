# 패턴 색인

만들려는 **상호작용**으로 찾는다. 사례 사이트는 카드의 패턴 칸에서 빌드가 모은다. 패턴마다 사례 카드는 `catalog.json`의 `patterns[].sites`나 보관함 패턴 탭에서 본다. 레이어 대응은 [docs/11](../docs/11-레이어-설정-시스템-설계.md) 용어로 적는다. 2026-09-30에 카드 7장을 Aside로 직접 열어 본 뒤 설명·레이어 대응·검수할 점을 관찰에 맞게 고쳤다. 2026-10-01에 인스타그램 리포스트·DM에서 카드 8장(✅ 3 · ⏸ 5)과 패턴 7개를 더했다. `scene-form`·`pointer-reactive`·`card-dashboard`·`media-hero`는 ⏸ 카드만 사례라 근거로 단정하지 않는다. 카드가 늘면 새 패턴은 그때 추가하고, 쓰는 카드가 없는 패턴은 지운다.

### `desktop-os` — 데스크톱 OS 은유

작업물·정보를 창·아이콘·폴더로 연다. 방문자가 이미 아는 조작(아이콘 열기, 창 닫기·끌기)을 탐색으로 쓴다. 참고 사례는 아이콘 하나를 누르면 정보 창이 여러 개 동시에 열리고 창 제목 줄을 끌 수 있었다.

| 항목 | 내용 |
|---|---|
| 맞는 의뢰 | 작업물이 많은 개인 포트폴리오, 레트로·장난스러운 콘셉트 |
| 패밀리 | 새 패턴 |
| 레이어 대응 | 배경화면 · 아이콘 그리드 · 창 프레임 · 창 내용 · 독(작업 표시줄) — 창 크기·처음 위치(창마다 다르게 열지)·열림 모션·아이콘 간격·아이콘 크기와 이름표 크기 |
| 검수할 점 | 아이콘에 Tab·Enter로 창이 열리는지, **Escape와 키보드로 창 닫기**(참고 사례는 마우스 전용 닫기 점), 창이 겹칠 때 뒤 창을 눌러 앞으로 오는지와 읽기 순서, 아이콘을 끌 수 있는 것처럼 보이는데 못 끄는 어긋남 없애기, 첫 로딩(이미지 수십 장이면 수십 초), 모바일에서는 창 대신 전체 화면 |

### `drive-to-explore` — 게임형 공간 탐색

방문자가 캐릭터·탈것을 움직여 공간을 돌아다니며 작업물을 발견한다. 참고 사례는 방향키·WASD로 차를 몰아 표지를 지나가고, Escape로 메뉴를 열고 닫는다.

| 항목 | 내용 |
|---|---|
| 맞는 의뢰 | 기억에 남아야 하는 개인·스튜디오 소개, 게임 감각이 브랜드인 곳 |
| 패밀리 | A' |
| 레이어 대응 | 월드(지형·오브젝트) · 플레이어 · 안내 표지 · HUD · 메뉴(조작 안내·Respawn) · 입장 연출 · 목록 대체 화면 — 이동 속도·카메라 거리·표지 문구·조작 안내 문구 |
| 검수할 점 | 키보드·터치 조작과 조작 안내, **조작 없이 작업 목록으로 바로 가는 경로(참고 사례에는 없어서 우리가 채워야 함)**, 길을 잃었을 때 Respawn·Unstuck 같은 복귀 버튼, Escape로 메뉴 열기·닫기, 일반 Tab 탐색이 안 되는 점과 동작 줄이기 대응 없음의 보완, 첫 로딩(참고 사례는 약 20초·번들 약 5MB)과 로딩 화면 |

### `moodboard-canvas` — 자유 배치 무드보드

작업 이미지를 격자 대신 자유롭게 흩어 놓고, 끌거나 훑으며 본다. 참고 사례의 무드보드는 작업을 전시하는 용도가 아니라, 흩어 놓은 스티커를 끌어 빈 포스터 위에 올려 **나만의 포스터를 만드는 참여형 놀이**였다(작품 목록은 타일 벽 페이지가 따로 맡았다).

| 항목 | 내용 |
|---|---|
| 맞는 의뢰 | 이미지 중심 작업(일러스트·사진·브랜딩) |
| 패밀리 | 새 패턴 |
| 레이어 대응 | 캔버스 배경(빈 포스터 크기·색) · 조각 풀(스티커·작업 카드의 위치·회전·크기) · 끌기 동작(드롭 범위·겹침 순서·놓을 때 효과) · 안내 문구 · 상세 오버레이 — 흩어짐 정도·카드 크기·끌기 관성 |
| 검수할 점 | **끌지 않고도 모든 조각·작업에 닿는 목록형 대체 경로**(참고 사례는 키보드로 스티커에 닿지 않았다), 조각마다 `alt` 슬롯(참고 사례는 104장 모두 비어 있었다), 초기화·되돌리기 버튼(참고 사례에 없음), 조각이 겹칠 때 읽기 순서와 포커스, 390px에서 목록형 대체 |

### `hand-drawn` — 손그림 표현

글자·선·버튼을 손으로 그린 질감으로 표현해 작가의 손맛을 첫인상으로 쓴다. 참고 사례는 길거리 한 장면을 통째로 그려 놓고 **그림 속 물건(표지판·소화전·비둘기)이 곧 메뉴 링크**였으며, 호버 때 그림 한 조각(차)이 움직였다.

| 항목 | 내용 |
|---|---|
| 맞는 의뢰 | 일러스트레이터·작가 포트폴리오 |
| 패밀리 | 새 패턴 |
| 레이어 대응 | 장면 배경 · 그림 링크(조각 이미지·위치·회전·이동할 주소·`alt` 슬롯) · 손글씨 문구(폰트·문구 파라미터) · 호버 모션(움직일 조각·길이·돌아올지) · 안내 말풍선 — 장식 이미지 교체·흔들림 모션·질감 불투명도 |
| 검수할 점 | 문구를 손글씨 이미지에 굽지 않기(참고 사례는 제목·메뉴·말풍선이 모두 `alt` 없는 그림이어서 스크린리더로는 읽을 글이 거의 없었다), 그림 링크에 Tab으로 닿고 이름이 있는지(참고 사례는 포커스가 body에 머묾), 호버 모션이 한 번 지나가고 돌아오지 않는 구조를 피하기, 대비 |

### `illustration-hero` — 일러스트 히어로 모션

첫 화면을 큰 일러스트와 그 일러스트의 움직임으로 채운다. 참고 사례는 광대 일러스트가 가만히 있어도 조금씩 흔들리고(그림 조각 100개 중 34개), 스크롤하면 층마다 다른 속도로 움직이며, 메뉴는 현수막 끄는 비행기 그림이었다.

| 항목 | 내용 |
|---|---|
| 맞는 의뢰 | 일러스트·애니메이션 작가, 캐릭터 IP |
| 패밀리 | 새 패턴 |
| 레이어 대응 | 히어로 일러스트(부위별 분리) · 배경(스크롤에 바뀌는 장면) · 메뉴 소품 · 연락처 배지 · 흐르는 작품 타일 줄 · 스크롤 안내 — 부위별 모션 강도·반복 속도·포인터 반응·스크롤 층 속도 비율 |
| 검수할 점 | **동작 줄이기에서 정지 프레임과 전체 끄기 스위치**(참고 사례는 끄는 경로가 없어 보였다), 첫 화면 로딩 용량(참고 사례는 그림 100개·첫 내용 약 3초), 계속 흐르는 타일 줄을 누르기 쉬운지와 멈춤, 메뉴 글자가 그림이라 읽히는지, Tab 접근 |

### `expand-gallery` — 클릭하면 펼쳐지는 갤러리

작은 사진을 누르면 그 자리에서 크게 펼쳐지거나 이어진 사진이 드러난다. 참고 사례는 사진을 누르면 **그 자리에서 4장으로 갈라지며 격자가 재배치**되고(다시 누르면 또 갈라짐), 호버 때 나오는 ↗ 버튼으로 전체 화면 라이트박스(이전·다음·닫기)를 따로 연다.

| 항목 | 내용 |
|---|---|
| 맞는 의뢰 | 사진·공간·제품 작업 |
| 패밀리 | 새 패턴 |
| 레이어 대응 | 썸네일 격자(마스크 모양·간격) · 갈라지기(장수·최대 깊이·접기 버튼) · 호버 버튼 · 라이트박스(배경 흐림·버튼 위치·키) · 머리글 버튼 — 펼침 크기·전환 길이·곡선·캡션 위치 |
| 검수할 점 | **갈라진 상태를 되돌리는 방법**(참고 사례는 Escape·재클릭으로 안 돌아왔다), Escape·←·→로 라이트박스 조작과 닫은 뒤 포커스 복귀(참고 사례는 잘 됨), 뒤로 가기(참고 사례는 주소가 안 바뀌어 사이트 이탈), 같은 이름의 버튼이 둘이 되지 않게 구분, 호버 전용 버튼의 터치 대체, 동작 줄이기에서 즉시 전환, 큰 이미지 지연 로드 |

### `video-tile-catalog` — 루프 영상 타일 카탈로그

결과물을 정지 이미지 대신 **짧은 루프 영상 타일**로 벽돌처럼 깔아 훑어 고르게 하고, 타일을 누르면 큰 미리보기 상세가 덮인다. 참고 사례는 화면에 들어온 타일만 재생하고, 상세를 주소 파라미터(`?prompt=…`)로 열어 Escape·뒤로 가기로 닫힌다.

| 항목 | 내용 |
|---|---|
| 맞는 의뢰 | 템플릿·프롬프트·배경 모음처럼 움직이는 결과물을 고르는 화면, 브랜드·제품 랜딩의 작업 예시 모음 |
| 패밀리 | D |
| 레이어 대응 | 제목·카테고리 알약 · 타일 벽(열 수·간격·타일 비율) · 타일 영상(재생 조건·포스터) · 상세 오버레이(영상·이름·분류·좋아요) — 열 수·재생 시작 거리·상세 전환 길이·알약 목록 |
| 검수할 점 | 화면 밖 타일은 멈춘 포스터인지와 전체 영상 용량(참고 사례는 첫 내용 약 3.6초), 타일 본체에 Tab으로 닿는지(참고 사례는 복사·좋아요 버튼만 잡혔다), 상세를 Escape·뒤로 가기·← 버튼으로 닫기, 카테고리 필터가 실제로 타일을 바꾸는지, **동작 줄이기에서 영상 자동 재생 정지**(참고 사례는 끄는지 확인 못 함), 터치 기기에서 호버 없이 미리보기 |

### `scene-form` — 장면을 입힌 입력 폼

로그인·비밀번호 입력처럼 평범한 폼을 **배경 장면·캐릭터·버튼 상태 연출**로 감싸 첫 화면의 놀이로 만든다. 폼 구조는 그대로 두고 입력·성공·실패에 맞춰 장면이 반응한다. 2026-10-01 사례는 둘 다 릴스 캡처로만 봤다(⏸).

| 항목 | 내용 |
|---|---|
| 맞는 의뢰 | 회원 전용 공간 입구, 이벤트·한정판 입장 화면, 브랜드 첫인상이 중요한 가입 화면 |
| 패밀리 | 새 패턴 |
| 레이어 대응 | 배경 장면 · 폼 카드(블러·불투명도·기울기) · 버튼 연출(대기·누름·성공·실패 상태별 그림과 문구) · 반응 캐릭터(상태별 프레임) · 안내 문구 — 연출 길이·기울기 최대 각도·캐릭터 반응 강도 |
| 검수할 점 | 입력란 라벨과 대비(어두운 유리 카드), **실패·로딩 상태도 연출이 있는지**(사례는 성공만 보였다), 연출 중에도 Enter로 제출되고 포커스가 남는지, 동작 줄이기에서 장면 반복 정지, 연출이 제출을 늦추지 않는지 |

### `pointer-reactive` — 포인터를 따라 반응하는 요소

카드가 포인터 쪽으로 기울거나, 캐릭터 시선이 포인터를 따라오거나, 지나간 자리에 이미지 꼬리가 남는다. 화면을 "살아 있게" 하는 작은 반응이고 정보를 담지 않는다.

| 항목 | 내용 |
|---|---|
| 맞는 의뢰 | 캐릭터·제품 첫 화면, 포트폴리오 히어로, 게임풍 랜딩 |
| 패밀리 | 새 패턴 |
| 레이어 대응 | 반응 대상(카드·캐릭터·물체) · 트레일 — 반응 범위·최대 각도·방향 프레임 수·따라가는 속도·되돌아오는 시간·트레일 간격과 수명 |
| 검수할 점 | **터치·키보드에서는 정지 상태가 기본**인지(포인터가 없으면 아무 일도 없는 화면이 되지 않게), 동작 줄이기에서 반응 0, 포인터가 떠나면 원위치, 반응 때문에 글자가 흔들려 읽기 어려워지지 않는지, 프레임 이미지 용량 |

### `card-dashboard` — 카드형 대시보드 마이크로 인터랙션

여러 정보 카드를 격자로 나누고 카드 공통의 작은 반응(호버 리프트·툴팁)과 목록 → 상세 패널 흐름을 둔다. 강조색은 행동을 부르는 카드 한두 장에만 쓴다.

| 항목 | 내용 |
|---|---|
| 맞는 의뢰 | 관리자 화면, 개인 기록·통계 화면, 작품 운영 대시보드 |
| 패밀리 | 새 패턴 |
| 레이어 대응 | 사이드바 · 카드 격자(열 수·간격·모서리·블러) · 카드 모션(리프트 거리·길이) · 강조 카드(색·대상) · 상세 패널(폭·전환) — 카드 안 숫자·목록은 콘텐츠 데이터 |
| 검수할 점 | 호버 전용 정보가 없는지(포커스로도 보이는지), 차트 값을 글로도 읽을 수 있는지, 카드 순서와 Tab 순서가 같은지, 좁은 폭에서 카드 열 수 줄이기, 동작 줄이기에서 리프트 0 |

### `media-hero` — 풀블리드 영상 히어로와 수치 바

첫 화면 전체를 영상·큰 사진으로 채우고, 얇은 메뉴·버튼 두 개·핵심 수치 바만 얹는다. 화면을 훑는 몇 초 안에 결정에 필요한 숫자를 보여 준다.

| 항목 | 내용 |
|---|---|
| 맞는 의뢰 | 공간·부동산·여행·제품 랜딩, 전시 소개 첫 화면 |
| 패밀리 | D |
| 레이어 대응 | 히어로 미디어(영상·포스터·덮개 어둡기) · 상단 메뉴 · 히어로 문구 · 버튼 쌍 · 수치 바(항목 수·불투명도·위치) |
| 검수할 점 | 영상 위 글자 대비, 포스터 이미지와 첫 화면 로딩 용량, **동작 줄이기에서 영상 정지**와 일시정지 버튼, 좁은 폭에서 수치 바가 줄바꿈되어도 읽히는지 |

### `scroll-journey-3d` — 스크롤로 따라가는 3D 여정

스크롤 진행률 하나로 3D 카메라 경로, HUD 숫자, 단계 패널을 함께 움직여 "어딘가를 지나가는" 경험을 만든다. 참고 사례는 같은 여정을 스크롤·자동 재생(배속·±10초·탐색 슬라이더)·자유 비행 세 방식으로 보게 했고, 모바일에서는 3D 대신 글 기록을 보여 줬다.

| 항목 | 내용 |
|---|---|
| 맞는 의뢰 | 여행·탐험·역사 연대기, 공간·전시 소개, 긴 과정(제작 과정·성장 기록)을 따라가는 이야기 |
| 패밀리 | A |
| 레이어 대응 | 월드(지형·텍스처·안개) · 카메라 경로(단계별 위치·시선·보간) · HUD(항목·단위·카운트) · 단계 패널(콘텐츠 데이터) · 단계 목록 · 재생 컨트롤(배속·건너뛰기) · 로딩 화면(단계 문구) · 모바일 대체(글 기록) — 장면은 단계로 선언, 진행 입력은 스크롤·자동 재생 |
| 검수할 점 | **단계 목록으로 바로 가기**(참고 사례는 목록을 CSS로 꺼서 슬라이더뿐이었다), 보이지 않는 요소가 포커스를 받지 않는지, 일시정지가 Space로도 되는지, 첫 진입 시간과 로딩 문구(참고 사례 Aside 기준 약 25초), 모바일·WebGL 없음 대체 화면, 동작 줄이기에서 부드러운 스크롤·카운트업 끄기, 픽셀 비율 상한 |

### `scroll-product-story` — 스크롤로 넘기는 제품 이야기

제품 하나를 스크롤 진행률에 맞춰 장면(통째 → 갈라짐 → 클로즈업 → 사용 순간)으로 보여 주고 구매 고르기로 끝낸다. 참고 사례는 영상 대신 **이미지 1,000장 시퀀스를 캔버스 한 장에** 그리고, 문구를 프레임 속 물체 좌표에 붙였다.

| 항목 | 내용 |
|---|---|
| 맞는 의뢰 | 음료·화장품·전자 기기 같은 단일 제품 랜딩, 신제품 공개 페이지 |
| 패밀리 | 새 패턴 |
| 레이어 대응 | 필름(프레임 목록·장수·해상도 묶음·진행률 지도·cover/fit·대표 프레임) · 진행 막대 · 장면 문구(진행률 구간·붙을 물체 좌표) · 상단 메뉴(이동할 진행률) · 구매 섹션 · 서랍 — 장면은 진행률 구간으로 선언 |
| 검수할 점 | **첫 방문 전송량**(참고 사례는 프레임 약 90MB를 모두 미리 받았다 — 앞 구간만 먼저 받고 나머지는 늦게), 거친 입력 기기용 저해상도 묶음, 동작 줄이기에서 대표 프레임 한 장, 키보드(PageDown·Space)로도 진행, 서랍·오버레이가 닫혀 있을 때 포커스를 잡지 않는지와 닫은 뒤 포커스 복귀, 메뉴 이동이 주소에 남는지 |

### `explorable-diagram` — 탐색하는 구조도

구조도·흐름도를 정지 그림이 아니라 탐색 도구로 만든다. 노드를 고르면 위·아래 흐름만 남고, 두 노드 사이 경로를 따라 카메라가 이동하며, 확대할수록 세부가 드러난다. 상태는 주소 해시로 공유한다.

| 항목 | 내용 |
|---|---|
| 맞는 의뢰 | 분기형 이야기 지도, 작품 구조 설명, 서비스·데이터 흐름 소개, 관리자용 장면 관계도 |
| 패밀리 | 새 패턴 |
| 레이어 대응 | 그림판(격자·구역) · 노드(모양·이름표 — 목록은 콘텐츠 데이터) · 관계선(굵기·흐름 모션) · 초점 효과(흐림 정도·확대율) · 경로 재생(단계 간격) · 정보 패널 · 확대 단계(세부를 보일 배율) · 모션 정지 버튼 |
| 검수할 점 | 노드·관계선이 버튼으로 Tab·Enter에 닿는지(참고 사례는 잘 됨), Escape 한 번으로 모든 강조 해제, 상태 해시 공유와 뒤로 가기, 휠 확대·끌어서 이동·터치 핀치(참고 사례에 없음), 흐린 노드 글자 대비, 동작 줄이기와 사용자 정지 버튼 |
