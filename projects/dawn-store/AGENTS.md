# AGENTS.md — Codex 작업 규약

프로젝트: `dawn-store` (새벽 세 시 · Still Open)
당신의 역할: 이 폴더의 기획 산출물을 받아 **구현 전부와 이미지 생성**을 담당한다.

## 먼저 읽을 것 (이 순서로)

1. `SPEC.md` — 계약이다. 여기 없는 기능을 추가하지 않는다
2. `seed/story.json` — 7컷 그래프. 그대로 `app/public/story.json`으로 복사해 쓴다
3. `seed/theme.json` — 디자인 토큰. 그대로 `app/public/theme.json`으로 복사해 쓴다
4. `wireframes/index.html` — 브라우저로 열어라. 화면 6종의 요소 배치와 실측 크기가 들어 있다
5. `assets/PROMPTS.md` — 이미지 생성 프롬프트

`../../docs/08-레퍼런스-심층분석-aimovie-dyw.md`는 근거 문서다. 왜 이렇게 설계했는지 궁금할 때만 본다.

## 작업 순서

각 단계가 끝나면 커밋한다. 앞 단계의 검증이 통과하기 전에 다음으로 넘어가지 않는다.

| 단계 | 내용 | 통과 조건 |
|---|---|---|
| 1 | 스캐폴딩. Vite + React + TS, `app/` 아래. `seed/`의 JSON 두 개를 `app/public/`으로 복사 | `npm run dev`가 뜬다 |
| 2 | zod 스키마(`src/schema/`)로 두 JSON을 파싱. 타입 추출 | 두 파일이 검증을 통과한다 |

| 4 | `theme.json` → CSS 변수 주입(`src/theme/`) | 개발자 도구에서 변수가 보인다 |
| 5 | 플레이어 코어. 미디어 추상화, 듀얼 레이어 크로스페이드, 타이머, 프리로드 | 플레이스홀더 이미지로 7컷이 순서대로 넘어간다 |
| 6 | 그래프 엔진. 노드 이동, 플래그, 글로우 상태기계, `available` 방어 | 수용 기준 2·3번 통과 |
| 7 | UI. 화살표, 메뉴, 핫스팟, 자막, 스킵, 언어 토글, 푸터 | 와이어프레임과 대조해 일치 |
| 8 | 타임라인, 히든 링크, 엔딩 화면 | 수용 기준 4·5·6번 통과 |
| 9 | 이미지 8장 생성 후 WebP 변환, 핫스팟 좌표 보정 | 성능 예산 통과 |
| 10 | 모바일 대응 검증, 성능 측정 | 수용 기준 10개 전부 통과 |

## 규칙

**하지 말 것** (SPEC §11의 요약이다. 어기면 되돌린다)

1. 분기 정보를 `edges` 밖에 중복 저장하지 않는다
2. 색·크기·간격을 코드에 직접 쓰지 않는다. 전부 CSS 변수
3. `available: false` 노드로 가는 버튼을 DOM에 만들지 않는다. `display: none`이 아니라 렌더링 자체를 건너뛴다
4. 상태 라이브러리, UI 프레임워크, 애니메이션 라이브러리를 추가하지 않는다
5. 관리자 화면을 만들지 않는다
6. 폰트 풀팩을 번들하지 않는다. 한국어와 라틴 서브셋만, 파일 6개 이하
7. 자막·효과음을 기본 꺼짐으로 두지 않는다

**할 것**

1. 설계와 다른 결정이 필요하면 `SPEC.md`를 먼저 고치고 그 이유를 커밋 메시지에 쓴다
2. 타입은 zod 스키마에서 뽑아 쓴다. 손으로 인터페이스를 다시 쓰지 않는다
3. 좌표 계산은 화면이 아니라 **미디어 요소의 렌더 박스** 기준으로 한다. `object-fit: cover`로 이미지가 잘려도 핫스팟이 사물 위에 붙어 있어야 한다
4. 파일 하나가 300줄을 넘으면 쪼갠다

## 이미지 생성

`assets/PROMPTS.md`의 순서를 지킨다. **`hub`를 먼저 만들고 그것을 참조로 나머지를 만든다.** 공간 일관성이 이 작품의 유일한 기술적 난제다.

`reflection`은 `dawn`을 참조로 넣고 반사 부분만 바꾼다. 두 이미지의 구도가 어긋나면 엔드 프레임 연속성이 깨지고, 그게 이 작품에서 가장 중요한 연출이다.

변환:

```bash
ffmpeg -i in.png -vf "scale=1920:-2" -c:v libwebp -quality 80 -compression_level 6 out.webp
```

컷당 400KB를 넘으면 quality를 70까지 내린다. 그래도 넘으면 긴 변을 1600으로 줄인다.

이미지가 나오면 `seed/story.json`의 `hotspot` 좌표를 실제 사물 위치에 맞춰 고친다. 지금 값은 추정치다.

## 검증

```bash
npm run lint:graph     # 그래프·자막·타임라인 정합성
npm run build          # 성능 예산 확인
npm run preview        # 수동 확인
```

수용 기준 10개는 `SPEC.md` §10에 있다. 전부 통과할 때만 완료를 선언한다. 특히 9번(모바일 토큰 적용)은 레퍼런스 두 사이트가 실제로 실패한 지점이니 뷰포트 리사이즈가 아니라 모바일 에뮬레이션으로 확인한다.
