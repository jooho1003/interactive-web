# 작업 동네 별도 페이지 설계 · 2026-10-03

Plan: ../../01-plan/features/village-page.plan.md

## Context Anchor
승인된 초기 동네를 별도 URL로 복원하고 동일 작품 데이터/운영 링크를 사용한다. 첫 선택 SASU, 메인 전시관 회귀 없음, 7작품·모바일·키보드·레이어 검수를 완료 조건으로 삼는다.

## 선택
A: 이전 저장소 전체를 복사 — 오래된 작품/운영 주소와 설정 복제 문제가 생긴다. B(채택): village.html + 전용 CSS/manifest, 기존 app.js·동네 scene/motion 재사용. C: 새 모델/이미지 — 초기 디자인 보존에 불필요.

## 구성
메뉴에 메인→작업 동네, 동네→전시관 링크. shared app은 body의 page 모드로 renderer/manifest/방문 저장 키만 선택한다. scene.js는 기존 파노라마에 6개 건물과 Day Walk 산책길 핫스팟을 표시한다. 파노라마 원본은 수정하지 않는다. 목록/검색/상세/설정/전시 편집은 기존 동작을 사용한다. 동네는 Blender 모델이나 전시관 배경을 로드하지 않는다.

## 상태·복구
걷기/입장 장면을 선언한다. 선택→카메라 이동→건물 이름 표시, 입장→원래 확대/페이드→실제 운영 주소. 머무르기 버튼/Escape/숨김/목록 전환으로 입장을 취소한다. Home/초기화는 SASU로 돌아온다. 동작 줄이기는 즉시 선택/운영 이동. WebGL 손실 시 기존 목록 대체를 유지한다. 동네와 전시관의 레이어/방문 복원은 별도 키, 콘텐츠/관람 설정은 공유한다.

## 레이어 계약·검증
Plan의 8개 레이어, 전용 village.layers.manifest.js/village.css. JS 입력은 attr 바인딩으로 실제 카메라/애니메이션에 반영하고 CSS는 위치/크기/색/보이기를 바인딩한다. 기존 panel은 manifest/work 저장 키를 선택한다. 집 좌표/원본 비율/최소 터치 크기/겹침 순서는 구조와 접근성상 fixed로 명시한다. 앱 check에서 동네 lint, browser에서 모든 파라미터 probe와 실제 렌더 값, 양방향 링크/7개 운영 href/키보드·모바일·빈 결과·저장 실패를 확인한다.

## 검수 결과·조정
동네 42/42 probe와 62개 검사 모두 3화면에서 PASS. 산책길 이름표의 top/bottom을 함께 제한하고 탑 이름표와 선택에 따라 분리해 번호/안내 겹침을 해결했다. 화면 밖 링크로 취소 포커스를 보낼 수 없을 때 공간에 복귀한다. 전시관 회귀와 레이어 57개는 유지된다. 상세 근거는 [QA-village.md](../../../QA-village.md).
