## Potato Designer에서 확인한 구현 지식

근거: [앱 README](../projects/potato-designer/README.md), [검수 기록](../projects/potato-designer/QA.md), [구현](../projects/potato-designer/dist/app.js).

| 관찰한 문제 또는 패턴 | 구현 방법 | 다음에 확인할 것 |
|---|---|---|
| 캐릭터 그리드 자식이 부모보다 커져 헤더·푸터를 침범 | 그리드 자식의 최소 크기를 0으로 지정하고 무대 영역에 표시 범위 제한 | 실제 자산 로딩 후 부모·자식 치수와 화면 캡처 |
| 좁은 모달의 `1fr` 트랙이 카드 최소 너비에 밀림 | `minmax(0,1fr)`와 반응형 글자 크기 | 320px에서도 가로 스크롤 없이 마지막 카드 선택 |
| 정지가 선택한 장면까지 초기화 | 사용자 정지·OS 동작 줄이기·일시적 배경 정지를 구분하고 장면 데이터 보존 | OS 설정 전환, 상세 패널, 작업 선택 후 정지 의도 유지 |
| CSS 모션과 기능 상태가 섞이기 쉬움 | 이미지/포인터/등장 레이어를 분리하고 상태 변화는 데이터로 제어 | 모션 없이도 검색·선택·저장이 가능해야 함 |
| localStorage는 실패하거나 오염될 수 있음 | 읽기·쓰기 예외 처리, ID와 구조 검증, 현재 세션 동작 유지, 파일 저장 대안 | 새로고침·저장소 차단·잘못된 데이터 |
| 단순한 카드 클릭이 분위기 변경에 그침 | 작업 탐색→상세 이해→관심 저장→참고 작업을 메모에 연결 | 기존 메모 본문 유지, 연결 해제, 다운로드 내용 |
| 검색·상세·초안에서 작업 이름이 중복될 수 있음 | [work-data.js](../projects/potato-designer/dist/work-data.js)의 안정된 ID로 연결 | 유효하지 않은 저장 ID는 버리고 사용자 입력을 HTML로 삽입하지 않음 |
| 모달 간 이동 시 포커스가 숨은 버튼에 남음 | 바깥의 원래 진입 버튼을 기억하고 마지막 모달을 닫을 때 복귀 | 키보드로 상세→메모→Escape 흐름 확인 |

기존 52개와 신규 탐색·관심·참고 작업 연결 40개 브라우저 검사, 데이터 테스트 4개가 통과했다. 상세 근거와 미검수 범위는 앱 QA 기록에서 확인한다. 도구의 기존 탭에서 시간 초과가 반복되었지만 새 탭에서는 통과했다. 이런 경우 앱 결함과 검수 환경 문제를 구분하고, 실패한 검사를 통과로 간주하지 않은 채 새 환경에서 재현한다.

## 3D 공통 제작 결정과 구현 경계 (2026-09-23)

2026-10-04 우선순위: 인터랙티브 웹은 [14번](14-2.5D-이미지-제작-방식.md)의 3D 느낌 이미지 방식을 **주로** 쓴다(사용자 결정). 이 절의 실제 3D 경로는 14번 §1의 예외 조건일 때 적용한다.

실제 3D가 필요할 때의 사용자 선택은 **Meshy → Blender → Three.js**다. 숏폼과 웹이 같은 Blender 자산 정본을 사용하되 영상용 원본과 웹용 경량 GLB를 별도로 출력한다. [13번 설계](13-3D-공통-제작-파이프라인-설계.md)에 자산 ID·revision, 부품/재질/클립, 원본 백업, 프롬프트 카드, 레이어 계약과 첫 POTATO 검증 범위를 정리했다. 기존 자료의 Tripo 우선안보다 이 결정을 먼저 따른다.

- 현재 layer-kit 실제 구현은 CSS/text/attr와 DOM probe다. 11번의 fn·캔버스 선택 설계가 이미 구현됐다고 가정하지 않는다. 3D 도입 시 비DOM 레이어 적용·바인딩 lint·실제 렌더 관찰 probe를 추가해야 한다.
- 기존 PNG의 원근 회전과 실제 GLB의 뼈대 애니메이션은 검수 대상이 다르다. DOM 619/619 기록을 3D 통과 근거로 사용하지 않는다.
- 생성 성공은 파일 수집·Blender 보정·웹 전달 성공을 뜻하지 않는다. 임시 모델 URL 대신 버전/해시가 있는 원본과 두 출력물을 보관한다.
- 자산 카탈로그는 콘텐츠이고, 장면에 놓인 인스턴스/부품의 모양과 반응이 레이어다. 레이아웃과 모션 속도의 정본은 layers.values로 한정한다.
- 이번 확인 범위는 저장소 코드와 공식 문서 및 설계다. 실제 생성·Blender export·3D 브라우저 probe·모바일 성능은 후속 검수 대상이다.

## 다음 작업에서 기록할 최소 항목

관리자 UX 레퍼런스: [Choreographic 장면·전환 편집 방식](research/choreographic-admin-reference.md). 장면 썸네일→미리보기→레이어 조절→전환 재생을 [Scene Studio](12-Scene-Studio-관리자-설계.md)에 적용했다. 페이지 순서, 장면 상태, 사용자 입력 대기와 시간 기반 모션을 구분한다. Potato Designer가 첫 소비자이며 다른 앱 이관은 후속이다.

Scene Studio에서 새로 확인한 것:

- 기존 버튼용 `data-scene`과 런타임 루트의 속성을 공유하면 루트에 버튼 동작이 연결된다. 루트는 `data-layer-scene`으로 분리한다.
- 부모 iframe과 자식의 객체는 서로 다른 realm이다. 엄격한 plain-object 검증 전에 자식에서 JSON 값으로 다시 생성한다.
- CSS 단축 속성의 custom property는 CSSOM의 개별 longhand에 빈 문자열로 보일 수 있다. probe는 원래 선언을 읽고 계산 스타일을 비교한다. 화면 숨김 검사 중에는 rAF가 멈출 수 있어 타이머와 동기 스타일 계산으로 진행한다.
- 공통 패널과 개별 패널이 같은 DOM을 가리킬 때 값이 덮이지 않도록 이동/회전은 합, 크기/불투명도는 곱으로 합성한다. 애니메이션 opacity도 같은 합성값을 사용한다.
- 화면 선택은 가장 작은 사각형보다 실제 그려지는 순서와 조상 레이어를 먼저 사용한다. 드래그는 pointer capture로 유지하고 전체 제스처를 한 번에 되돌린다.
- 편집 기본 프레임이 0초이면 등장 전의 투명한 캐릭터가 보이지 않는다. 안정된 시점을 기본으로 하고 처음/재생을 별도로 제공한다.
- 저장 실패 시 화면값을 지우지 않는다. 충돌을 알리고 게시를 막으며 내보내기를 제공한다. 게시 테스트는 임시 프로젝트 복사본에서 실행한다.
- 관리자에서 실제 앱을 체험하며 장면/모달을 바꾸면 부모의 선택 상태도 동기화해야 한다. 미리보기와 별도의 복제 렌더러를 만들지 않는다.

검수 결과: 브라우저 140개, 레이어 probe 619/619, lint 오류 0, 전체 워크스페이스 검사 통과. 조건부 스타일 활성화 검사와 실제 브라우저/기기 검수 범위의 차이는 [QA](../projects/potato-designer/QA.md)에 명시했다.

- 참고한 문서·기존 코드와 적용 이유
- 입력 → 바뀌는 상태 → 보이는 피드백 → 취소·복구 방법
- 작품 데이터와 공통 동작의 경계
- 새로 확인된 결함, 원인, 해결 방법
- 실행한 검수와 미검수 범위

단순 수치 수정까지 문서를 반복 복제하지 않는다. 새로 얻은 지식이나 기존 원칙이 바뀔 때 이 기록을 갱신한다.

- Git 체크아웃은 텍스트 줄바꿈을 바꿀 수 있다. 생성물 최신성 검사는 입력·출력의 CRLF/LF를 정규화한 뒤 비교하고, 내용이 바뀐 경우에는 여전히 실패해야 한다. Potato의 build-layers.test.mjs에서 재현·검증했다.

## 레퍼런스 보관소에서 확인한 것 (2026-09-30)

- 확인됨: Aside 창은 1440×900으로 열리지만 조작 도중 1050·1330·1440px로 바뀐 적이 있다. 캡처마다 `innerWidth`를 읽어 카드에 적는다. `setViewportSize`·`emulateMedia`·CDP·녹화 API는 없다. 스크린샷은 Aside 세션 폴더의 상대 경로로만 저장되어 `pwd()` 위치에서 복사해야 한다. `file://`은 막혀 로컬 서버로 연다. 스크롤·이동 직후 스크린샷이 시간 초과로 실패해도 기다렸다 재시도하면 성공했다.
- 확인됨: 직접 연 7곳은 대부분 키보드 대체가 없다. 창 닫기가 마우스 전용(bychudy), Tab 포커스가 body에 머묾(annamills·clarakirkpatrick·loonamessal). bruno-simon은 작업 목록 경로를 못 찾았다. julesesick은 키보드 대체 문제가 아니라 **되돌리기 결함**이다: 갈라진 사진을 되돌릴 방법이 없다. 카드의 "안 가져올 것"과 패턴의 "검수할 점"에 옮겼다.
- 확인됨: Aside 캡처에는 오른쪽 가장자리(약 x=1258, y=152)에 Aside의 떠 있는 버튼이 찍힌다 — 사이트 UI가 아니다.
- 확인됨(보관함 결함, 검수에서 발견): 카드마다 캡처가 2장인데 파서가 첫 이미지만 읽고 렌더러가 이미지 문단을 통째로 빼서 두 번째 캡처가 어디에도 안 보였다. 모든 이미지를 읽도록 고쳤다. 패밀리 정규식이 `3D`·`B2B`의 숫자 뒤 글자를 패밀리 D·B로 읽어, 앞 글자 검사에 숫자를 넣어 고쳤다.

### 2026-10-02 · 깨끗한 건물과 재질 얼룩
LAB 사용자는 풍화된 촬영 석재보다 이전의 깔끔한 건물을 선호했다. 깨끗한 현대 건축에는 큰 명암 얼룩·작은 돌무늬를 제거하고 실제 줄눈·미세 입자·빛의 반응을 남긴다. 노멀 강도만 줄이면 diffuse 얼룩은 사라지지 않는다. 재질 교체 뒤에도 옛 색 베이크의 emission과 저샘플 AO가 얼룩을 되살릴 수 있어 함께 확인해야 한다. |---|---|---|
| 덮개 안 iframe의 `src`를 바꿀 때마다 브라우저 기록이 쌓여, 덮개를 닫는 `history.back()`이 목록 주소가 아니라 iframe 안에서 움직였다 | 첫 이동(빈 iframe)만 `src`, 이후는 `iframe.contentWindow.location.replace(url)` | 한 iframe에 여러 페이지를 번갈아 띄우는 미리보기·라이트박스 |
