## 0. 결론 먼저

**"작품을 찍어내는 툴"은 장르가 아니라 "설정값 비중"이 결정한다.** 한 장르에서 화면에 보이는 것 중 JSON 설정으로 표현되는 비중이 높을수록 복제 → 관리자 조정으로 양산이 되고, 알고리즘·룩·하드웨어가 창작의 핵심이면 매번 커스텀이다. 이 기준으로 보면 기존 5개 패밀리(A/A'/B/D/E)는 전부 양산 가능 영역에 있고, 여기에 **F. 바이럴 퀴즈/진단**을 추가하면 국내 시장에서 가장 회전이 빠른 장르가 채워진다.

툴은 파이프라인 8단계(컨셉 → 에셋 → 스캐폴딩 → 구현 → 관리자 → QA → 배포 → 운영)마다 **"사람이 고르는 단계"와 "API로 자동화하는 단계"를 분리**해서 꽂는다. 룩 탐색과 스타일 프레임은 사람(Midjourney·Flora), 그 이후 프랍 시트·3D 변환·압축·더빙·분기 컷은 fal.ai 게이트웨이 + Tripo + gltf-transform + ElevenLabs로 스크립트화한다. 개발은 Replit(의뢰별 산출물, 모바일)과 Claude Code(공장 자체: 제너레이터·공용 패키지·CI)로 역할을 나눈다.

## 1. 장르 지도 — 5개 패밀리를 어떻게 넓히나

### 1-1. 양산 판정 기준 (이 문서의 핵심 도구)

한 장르를 패밀리로 만들지 판단할 때 3개 질문을 던진다.

1. **설정값 비중**: 화면에 보이는 것 중 JSON으로 표현되는 비중이 높은가? (전시 메타데이터, 영상 그래프, 퀴즈 문항, 스크롤 챕터 = 높음 / 셰이더 알고리즘, LLM 페르소나 품질 = 낮음)
2. **에셋 교체만으로 다른 작품이 되는가?** 코드를 안 건드리고 GLB·영상·문항만 갈아끼워 새 의뢰가 나오면 양산.
3. **인프라가 기존 패밀리와 같은가?** WebSocket(협업 캔버스), LLM 대화 백엔드(디지털 휴먼), 하드웨어(키오스크)가 필요하면 별도 투자.

세 질문에 모두 "예"면 템플릿 양산, 하나라도 "아니오"면 "엔진 재사용 + 매번 아트디렉션"(부분 양산) 또는 커스텀이다.

### 1-3. 새 패밀리 F. `viral-quiz` — 바이럴 퀴즈/진단

**한 줄**: 문항 → 점수 → 결과 유형 → 결과 카드 → 카카오톡/인스타 공유. 3D도 영상도 없다. 관리자가 곧 제품이다.

| 영역 | 기능 | 설정 키 |
|---|---|---|
| 문항 | 질문·보기·보기별 가중치(유형별 점수), 이미지/GIF 보기, 문항 순서·랜덤 | `questions[]` |
| 결과 | 점수 구간 → 유형 매핑, 유형별 카피·이미지·추천 링크(제품/모집 페이지) | `results[]`, `mapping` |
| 결과 카드 | 유형별 OG 이미지 **서버 동적 생성**(satori/resvg 또는 Canvas), 카드 템플릿 편집 | `card.template` |
| 공유 | 카카오톡 공유 SDK(템플릿 메시지), 인스타 스토리용 세로 이미지, 링크 복사, 참여자 수 카운터 | `share.*` |
| 디자인 | 테마(색·폰트·배경), 진행 바, 인트로/로딩 문구, desktop/mobile 두 벌 | `design` (responsive) |
| 수집 | (선택) 이메일·전화 수집 + 경품 응모, 유형별 통계 대시보드 | `lead`, `stats` |
| 제약 | **카카오톡 인앱 브라우저 최적화**(무거운 애니메이션 금지, 첫 화면 ≤ 1 s) | 성능 예산 |

- 왜 최우선인가: 설정값 비중 ~100%, 에셋은 이미지 십수 장, 인프라는 D와 동일(Express + 이미지 생성 엔드포인트). **가장 빨리 만들 수 있고 가장 자주 팔린다.**
- 에셋 파이프라인 연결: 유형별 결과 이미지를 Flora Style Node + Nano Banana 2로 "같은 룩 16장"(프랍 시트 기법 그대로) 뽑는다. 강연자의 4×4 그리드 노하우가 3D가 아닌 곳에서도 그대로 재사용된다.
- 적합한 의뢰: 신제품 인지도 캠페인, 채용 직무 적합도, 대학·기관 모집("나에게 맞는 학과"), 팝업스토어 사전 참여, 전시 관람 유형.

### 1-4. 한국 시장에서 확인된 것

- **퀴즈/진단**: 위 F. 유통 채널은 카카오톡.
- **팝업스토어**: 2025년 오픈 수 전년 대비 79% 성장(3,077개, 1~11월 누적, 2차 집계 **(미확인)**). 온·오프 연동(사전 예약 → 현장 체험 → 공유 콘텐츠) 수요. F + D + 현장 키오스크(A) 조합이 하나의 패키지가 된다.
- **전시 키오스크**: 카메라·센서·프로젝터 결합이라 순수 웹 템플릿으로는 안 된다. A 패밀리에 "키오스크 모드"(전체화면, 자동 리셋, 오프라인 에셋)만 넣고, 하드웨어는 파트너에 맡긴다.
- **대학·기관 홍보**: 국내 입학처 사이트는 여전히 정보성. 인터랙티브 캠페인 실사례를 찾지 못했다 **(미확인)** → 미개척 틈새로 추정. F(학과 진단) + B(캠퍼스 투어 분기 영상)가 바로 제안 가능.
- **국내 준거 스튜디오**: 더즈 인터랙티브(풀커스텀 에이전시), 소이정 SOI.LAB 3D(3D 쇼룸 + LLM 관리 시스템, 2025 GDWEB 대상). 후자가 우리 포지셔닝과 가장 가깝다.

## 2. 툴 적용 방식 — 파이프라인 단계별

### 2-1. 전체 그림: 사람이 고르는 단계 vs API로 돌리는 단계

| 단계 | 사람이 한다 | 스크립트/API가 한다 | 툴 |
|---|---|---|---|
| ① 컨셉·룩 | 인스퍼레이션 리뷰, 스토리 한 문장, 룩 탐색, 스타일 프레임 1장 확정 | — | Midjourney(수동, API 없음), Flora Style Node, Google Stitch(UI 구조 탐색, 무료) |

### 2-4. 개발 툴체인 — Replit과 Claude Code의 역할 분담

**Replit Agent 4(2026-03)**: 멀티 아티팩트(한 Repl에 앱+관리자+모바일이 DB·시크릿·배포 공유), Parallel Agents, 모바일 클라이언트, 2026-09 Project Analytics 추가. 요금 Core $20~25/월 + 크레딧, Pro $100/월, Autoscale 기본 $2/월 + 사용량, Reserved VM $15~130/월. 커스텀 도메인은 Core 이상, PostgreSQL 호스팅은 Pro. 모노레포 인식은 없다.

**Claude Code**: 스킬(패밀리별 제작 절차 캡슐화) / 서브에이전트(에셋·QA 병렬) / 훅(규칙 100% 강제) / 워크트리(`-w`, 2026-02 정식) / `claude -p` + GitHub Action(CI). 이미 설치된 superpowers 스킬군(`using-git-worktrees`, `dispatching-parallel-agents`, `writing-plans`)이 그대로 뼈대.

| 역할 | Replit | Claude Code + 모노레포 |
|---|---|---|
| 새 패밀리 0→1 초안 | ◎ (강연자 방식) | ○ |
| 공장 자체(제너레이터·공용 패키지·CI·QA) | ✕ | ◎ |
| 의뢰별 산출물의 집(도메인·과금·클라이언트 접근) | ◎ 앱 1개 = Repl 1개 유지 | 빌드 산출물만 push |
| 폰에서 급한 카피·설정 수정 | ◎ | ✕ |
| 3~4개 프로젝트 병렬 | ○ (탭) | ◎ (워크트리, 리뷰 대역폭이 상한) |
| "관리자 우선" 규율 강제 | ✕ (프롬프트뿐) | ◎ (훅 + 스냅샷 테스트) |

**장기 방향**: 관리자·에셋 업로드·분기 편집이 자체 코드로 완성되면("툴 완성") Replit은 초안 실험실 + 호스팅으로 축소되고, 양산은 모노레포 파이프라인이 담당한다.

**"모든 기능은 관리자에서 조작 가능"을 코드로 강제하는 법** (CLAUDE.md만으로는 ~70%)

1. 설정 스키마는 `packages/config-schema`에만 존재 (단일 원천).
2. Vitest 스냅샷: 스키마의 모든 리프 필드가 관리자 섹션에 등록됐는지 검사. 누락 시 실패.
3. PostToolUse 훅: `apps/**`에 하드코딩된 색상·크기 리터럴이 생기면 경고(스키마 키를 쓰라고).
4. ESLint import-boundary: `apps/`에서 three/video 로직 직접 import 금지 (03 §7 규칙 2).
5. CI: size-limit(번들) + Lighthouse CI(성능 예산 04 §5) + Playwright 카메라 모킹 시나리오.

**스캐폴딩**: Nx는 이 규모(패밀리 3~6개)에 과함. **`turbo gen`(Plop 기반) + degit**으로 `tools/new-app` 구현. 템플릿을 계속 갱신하고 기존 앱에도 반영해야 하면 Copier 검토.

**QA**: Playwright Chromium에 `--use-fake-ui-for-media-stream --use-fake-device-for-media-stream`(카메라 권한·가짜 스트림), WebKit은 헤드리스 GPU 미지원이라 headed. 시각 회귀는 Playwright 내장 → 팀이 커지면 Argos($100/월 플랫).

### 2-5. 배포 — **[문서 반영]** 03 §6 수정

03 문서는 Replit 1순위, Vercel+Railway 대안이었다. 리서치 결과 **미디어 서빙 비용**이 결정 변수다.

| 경로 | egress | 판단 |
|---|---|---|
| Cloudflare R2 | **$0/GB**, 저장 $0.015/GB/월, 무료 10 GB | 영상·GLB·스플랫 전부 여기. `storage` 어댑터 `r2`를 `local`/`replit` 옆에 1순위로 |
| Cloudflare Pages | 정적 대역폭 무제한 | 프론트를 Replit 밖으로 뺄 때 |
| Replit Autoscale | 사용량 과금 | 앱 서버(API + 관리자). 강연자 워크플로우·모바일 유지 |
| Vercel | 1 TB 초과 $40/100 GB | 미디어 직접 서빙 금지. 프리뷰 용도만 |
| Railway / Fly.io | $0.05 / $0.02(북미·유럽) per GB | 백엔드 컴퓨트 대안 |

결론: **앱은 Replit, 미디어는 R2 + 커스텀 도메인 CDN.** 03 §2-6에 이미 어댑터 패턴이 있으므로 구조 변경 없이 우선순위만 바꾼다.

### 3-3. 법적 체크리스트 (납품 전)

1. **AI기본법 제31조**(2026-01-01 시행): 생성형 AI 산출물이 포함되면 사전 고지 + 생성물 표시(UI/로고, 외부 반출 시 워터마크). 관리자 "앱 정보" 탭에 `aiDisclosure` 문구 필드를 넣어 기본 노출. 적용 범위는 법률 자문으로 재확인 **(미확인)**.
2. **유명 IP 오마주 금지**: 마리오로얄 DMCA 사례. Mini Kingdom식 마리오·매트릭스 오마주는 **개인 포트폴리오까지만**, 클라이언트 납품에는 쓰지 않는다. Kling의 "저작권 블로킹이 느슨함"은 장점이 아니라 리스크 신호.
3. **템플릿 IP 카브아웃**: 계약서에 "베이스 템플릿·엔진·컴포넌트는 제작사 소유, 클라이언트는 최종 커스터마이징물 라이선스"를 명시. 없으면 work-for-hire가 템플릿을 끌고 간다. 해외 클라이언트는 별도 IP 양도 조항.
4. **도구 상업 라이선스**: Postshot Indie 이상, Marble Pro 이상, Midjourney 연매출 $1M 초과 시 Pro, Krea Basic부터. 소비자 플랜은 대부분 **면책 없음**(Runway 엔터프라이즈만 IP 면책).
5. **카메라·세션 리플레이 동의**: 카메라 권한 요청 전 "왜 필요한지" 고지(전환율에도 유리). 세션 리플레이는 EU 방문자 있으면 쿠키 배너에 별도 항목.

### 3-4. 지표

- 분기형(B·A'): **경로 완주율, 선택 지점 이탈률, 노드별 선택률 히트맵** → PostHog 커스텀 이벤트(`node_id` 속성) + 퍼널 + 세션 리플레이.
- 3D(A): 카메라 권한 허용률(업계 벤치마크 없음 **(미확인)** → 자체 계측), 첫 인터랙션까지 시간, 마우스 폴백 비율.
- F: 완주율, 공유율, 유형 분포, 리드 전환.
- 가벼운 사이트(D): Umami/Plausible로 충분.
