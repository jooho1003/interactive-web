# 09. 흐름 에디터 · 미디어 관리 설계

작성 2026-09-15. 대상: 패밀리 B(분기형 영상·이미지 작품) 양산용 **공용 툴**. 첫 적용 작품은 `dawn-store`.

`docs/03` §3-2 `core-admin`, §3-8 `flow-editor`의 구체화이며, §0-4 추출 트리거("두 번째 소비자")를 이 툴 자체가 충족한다 — 플레이어와 에디터가 같은 스토리 스키마를 쓰는 두 소비자다.

---

## 1. 무엇을 만드는가

사용자 요구 두 가지:

1. **흐름이 보여야 한다.** 작품의 장면(영상·이미지)이 어떤 선택지를 거쳐 어디로 흘러가는지 노드 캔버스로 본다. 레퍼런스: 강연 2편 13:14~15:00 Connect Idea 노드 캔버스, [Newtake](https://www.newtake.ai/)의 "Node Workflow + Infinite Canvas".
2. **사이트 안에서 영상을 추가·삭제한다.** 코드를 고치지 않고 관리 화면에서 "새 비디오 등록", 복사, Skip, 버튼 표시 초, 색 태그, 삭제, Update. 레퍼런스: gryun-aimovie 관리자 영상 목록(사용자 제공 캡처).

### 레퍼런스에서 가져오는 것 (캡처 판독)

| 캡처 | 요소 | 이 설계에서 |
|---|---|---|
| 노드 캔버스 | 썸네일 카드 노드(이미지 + 하단 라벨 `MONITOR`) | 장면 노드 |
| | 선택지 텍스트가 선 위에 떠 있음(`Monitor`, `Turn on the lamp.`) | 엣지 라벨 = 선택지 문구 |
| | 베이지 텍스트 박스(`asdsd`, `BACK`) | 메모 노드 (재생에 영향 없음) |
| | 점선 연결 | 숨은 링크(hidden edge) 표시 |
| | 좌상단 1·2·3 | 저장 슬롯 = 스냅샷 |
| | 상단 정렬·간격 슬라이더·확대 | 정렬 도구·줌 |
| | 하단 `Press 'Tab' key on a node to add a child node.` | 키보드 힌트 바 |
| | 우하단 `sel: none \| edit: no \| nodes` | 상태 바 |
| 영상 목록 | 행: `>` 펼치기 · 이름 · 🎨 색 · `복사` · `Skip` 토글 · 숫자 · `×` | 미디어 목록 행 |
| | 점선 "새 비디오 등록" 드롭 영역 | 새 장면 등록 |
| | 하단 `Update` | 초안 → 게시 |
| | 뒤에 작품이 비쳐 보이는 반투명 패널 | 작품 위 오버레이 편집 (미리보기 유지) |

### 하지 않는 것 (1단계)
- 노드 사이 AI 이미지·영상 생성(Connect Idea의 Generate) — fal.ai 어댑터는 후속 (`docs/07`)
- 서브 캔버스(노드 안 캔버스)
- 여러 사람 동시 편집
- 자막 타임라인 편집기 (기존 JSON 편집 유지, 후속)

## 2. 핵심 결정

| # | 결정 | 대안 | 이유 |
|---|---|---|---|
| D1 | **목록의 한 행 = 장면 노드 하나.** 미디어를 노드와 분리한 라이브러리로 만들지 않는다 | 미디어 라이브러리 + 노드가 `mediaId` 참조 | 레퍼런스도 영상 키가 곧 노드(`video43-3`). 현재 `story.json`이 `node.media`를 인라인으로 가진다 → 스키마 파괴적 변경 없음. 같은 영상을 두 노드가 공유할 일은 복사로 충분 |

| D3 | **캔버스는 React Flow(@xyflow/react 12, MIT)**, 자동 배치는 dagre | tldraw(워터마크 유료), 직접 SVG | `docs/07`·`r2` 기존 결정. 줌·팬·미니맵·선택·연결을 직접 만들지 않는다 |
| D4 | **편집기 코드는 관람 번들에 넣지 않는다.** 인증 뒤 동적 import | 같은 번들 | 관람 예산(dawn-store JS 150KB) 보호. React Flow는 편집기 청크에만 |
| D5 | **초안(draft) → Update(게시) 2단계.** 편집은 초안에만 쓰고, Update 시 검증 통과해야 게시 | 즉시 반영 | 캡처의 Update 버튼. 편집 중 깨진 그래프가 관람자에게 나가지 않게 |
| D6 | **저장소 어댑터 2종**: `local`(IndexedDB, 개발·오프라인) / `hub`(JUHO LAB Worker + R2, 소유자 전용) | 단일 | 작품은 허브 `/experiences/<id>/` 아래에서 같은 오리진으로 돈다 → 허브 API를 그대로 쓴다. 로컬에서도 편집·미리보기 가능해야 개발이 된다 |
| D7 | **공용 패키지는 소스 그대로 소비**(빌드 없는 내부 패키지, `exports`가 `src/*.ts`) | 패키지마다 빌드 + turbo | 소비 앱이 전부 Vite라 바로 트랜스파일한다. turbo는 여전히 보류(`docs/03` §0-2 결정 4) |
| D8 | **흐름 지도는 기본 소유자 전용.** 관람자 공개는 설정 `flowMap.public` | 항상 공개 | 분기 구조 전체가 스포일러다 |

## 4. 데이터 모델 변경 (`@iw/story-schema`)

기존 `story.json` v1을 그대로 읽는다. 추가는 전부 **선택 필드**라 기존 파일이 유효하다.

```ts
// node에 추가
editor?: {
  x: number; y: number;                         // 캔버스 좌표. 없으면 dagre 자동 배치
  color?: 'none'|'red'|'amber'|'green'|'blue'|'violet';   // 목록·노드 색 태그
  collapsed?: boolean;                          // 목록 행 펼침 기억 아님 — 캔버스 그룹 접기 예약
}
// story 최상위에 추가
notes?: Array<{ id: string; text: string; x: number; y: number; w?: number }>;   // 메모 노드(베이지 박스)
flowMap?: { public: boolean };                  // 기본 false
schemaVersion?: 1                               // 없으면 1로 간주
```

기존 필드와 목록 행 매핑:

| 목록 행 UI | 필드 |
|---|---|
| 이름 | `node.id` (표시는 `title.ko`, 보조로 id) |
| 🎨 색 | `node.editor.color` |
| Skip 토글 | `node.skippable` |
| 숫자 | `node.buttonShowBeforeEnd` (끝나기 N초 전에 선택지 표시) |
| 복사 | 노드 복제 (§6-3) |
| × | 노드 삭제 (§6-4) |
| 펼침 영역 | 미디어 교체·포스터·길이·루프·available·제목·질문·연결 목록 |

### 4-1. 그래프 검사 (`lint.ts`)
`dawn-store/app/scripts/lint-graph.ts`의 9개 규칙을 순수 함수로 옮겨 **CLI와 편집기가 같은 코드를 쓴다.** 결과는 `{ level: 'error'|'warn', nodeId?, edgeId?, code, message }[]`.

추가 규칙: 도달 불가 노드(warn), 끊긴 엣지 `to` 없음(error), 미디어 파일 없음/업로드 실패(error), 엔딩 없는 막힌 노드(error), 출구 없는 순환(warn), 버튼 표시 초 > 미디어 길이(error).

**Update는 error가 0개일 때만 활성.** warn은 확인 후 게시 가능.

## 5. 화면

### 5-1. 진입
- 작품 URL에 `?edit=1` 또는 관람 화면 설정 패널의 `작품 편집` → `ADMIN_MODE` 게이트(`docs/03` §3-2) → 통과 시 `import('@iw/story-editor')`.
- 허브 안(`/experiences/<id>/`)에서는 허브 소유자 인증(`oai-authenticated-user-email`)이 게이트. 로컬 개발은 `ADMIN_MODE=public`.
- 편집기는 작품 위 **오버레이**로 뜬다. 뒤의 플레이어는 계속 살아 있어 미리보기가 된다(캡처처럼 비쳐 보임).

### 5-2. 셸
```
┌───────────────────────────────────────────────────────────────────────────┐
│ ● 초안 · 저장됨 12:04   [흐름] [미디어] [검사 ⚠2]      슬롯 [1][2][3]  [Update] [×] │
├───────────────────────────────────────────────────────────────────────────┤
│                         (탭 내용)                                            │
├───────────────────────────────────────────────────────────────────────────┤
│ Tab 자식 · Enter 형제 · Del 삭제 · F 맞춤        sel: hub │ edit: yes │ nodes 8 │
└───────────────────────────────────────────────────────────────────────────┘
```
- 좌상단 상태: `초안 · 저장됨 hh:mm` / `저장 중…` / `저장 실패 — 다시 시도` / `게시본과 같음`.
- 슬롯 1·2·3: 누르면 "현재 초안을 슬롯 N에 저장 / 슬롯 N 불러오기" 메뉴. 불러오기는 초안을 교체(되돌리기 가능).
- `Update`: 검사 → 확인 대화상자("게시본을 바꿉니다. 변경: 노드 +1 −0, 미디어 2개 교체") → 게시.
- 데스크톱 전용 레이아웃(≥ 1024px). 모바일에서는 `미디어` 탭만 1열로 제공하고 `흐름` 탭은 읽기 전용 지도.

### 5-3. 흐름 탭 (노드 캔버스)
```
 [정렬 ⇤ ⇹ ⇥] [간격 ━━●━━ 300] [자동 배치] [맞춤]  [🔍 노드 찾기]      [미니맵 ▣]
 ┌─────────┐  문을 연다    ┌─────────┐   계산대를 본다  ┌─────────┐
 │ [썸네일] │─────────────▶│ [썸네일] │────────────────▶│ [썸네일] │
 │ INTRO   │              │ HUB  ▶2 │                 │ COFFEE  │
 │ 8s      │              │ 12s ⏭  │─ ─ ─ 00:11~16 ─▶ │ 🔴 없음 │
 └─────────┘              └─────────┘   (숨은 링크)     └─────────┘
       ┌──────────┐
       │ 메모: BGM │
       └──────────┘
```
**장면 노드 카드**: 포스터/이미지 썸네일(영상은 호버 시 무음 재생), 하단 라벨 `title.ko`, 우상단 배지 — `▶` 영상 / `🖼` 이미지, `⏭` skippable, `∞` loop, `END` 엔딩, `START` 시작, 색 태그 띠, 검사 오류 시 빨간 테두리 + 개수. `available:false`는 반투명 + 사선.

**엣지**: `menu` = 실선 + 선택지 문구 라벨, `arrow` = 실선 + 방향 아이콘, `hidden` = 점선 + `00:11~00:16`. 선택하면 라벨 인라인 편집.

**조작**
| 입력 | 동작 |
|---|---|
| 노드 선택 후 `Tab` | 자식 장면 생성 + menu 엣지 연결 + 제목 입력 포커스 (캡처 힌트) |
| `Enter` | 형제 장면 생성(같은 부모에서 새 엣지) |
| `Delete` | 선택 삭제 (§6-4 규칙) |
| 핸들 드래그 → 다른 노드 | 엣지 생성(기본 menu, 문구 입력) |
| 핸들 드래그 → 빈 곳 | "새 장면 / 기존 장면 연결" 메뉴 |
| 빈 곳 더블클릭 | 메모 노드 |
| 파일을 캔버스에 드롭 | 드롭 위치에 새 장면(§6-1 업로드) |
| 노드 더블클릭 | 오른쪽 인스펙터 열기 |
| `Space`+드래그 / 휠 | 팬 / 줌 |
| `Ctrl+Z` / `Ctrl+Shift+Z` | 되돌리기 / 다시 (초안 히스토리 100단계) |
| `P` | 선택 노드부터 미리보기 재생 |

**흐름 읽기 기능** (요구 1의 핵심)
- **재생 추적**: 뒤의 플레이어가 재생 중인 노드를 캔버스에서 펄스 강조, 지나온 경로 엣지를 굵게. 플레이어 ↔ 편집기는 같은 페이지 이벤트 버스.
- **경로 보기**: 노드 선택 시 START에서 그 노드까지 도달 경로들을 강조, 그 노드에서 도달 가능한 엔딩 목록 표시.
- **길이 합산**: 경로 위 미디어 길이 합(예: "이 경로 1분 42초").

**인스펙터(오른쪽 패널)**: 노드 — 제목 ko/en, 타입, 미디어(교체 드롭존·포스터·길이·Ken Burns), skippable, 버튼 표시 초, loop, available, 질문, glow, 오디오. 엣지 — 종류, 문구 ko/en, 방향, 핫스팟(영상 위 드래그로 사각형), 숨은 링크 시간창.

### 5-4. 미디어 탭 (영상 목록)
```
 [🔍 검색] [색 ▾] [종류 ▾] [정렬: 흐름 순 ▾]                       8개 · 312MB
 ┌──────────────────────────────────────────────────────────────────┐
 │ >  intro · 유리문        🎨  [복사]  [Skip]  [ 5 ]  ✕            │
 │ ∨  hub · 계산대          🎨  [복사]  [Skip●] [ 5 ]  ✕            │
 │    ┌────────────┐  파일  hub.webm  12.0s  1920×1080  8.2MB   [교체]│
 │    │ [미리보기] │  포스터 [자동 추출] [업로드]   루프 □  공개 ■       │
 │    └────────────┘  들어오는 연결 2 · 나가는 연결 3  [흐름에서 보기]   │
 │ >  coffee · 커피        🔴  [복사]  [Skip]  [ 5 ]  ✕  ⚠ 파일 없음  │
 ├╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌┤
 ┆  + 새 비디오 등록 — 파일을 끌어 놓거나 눌러서 선택 (영상·이미지)       ┆
 └╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌┘
                                                          [Update]
```
- 행 컨트롤은 캡처 순서 그대로: 펼침 · 이름 · 색 · 복사 · Skip · 숫자 · 삭제.
- 숫자 입력: 0~미디어 길이, 정수 초. 범위 밖이면 빨간 테두리 + 검사 오류.
- `Skip` 토글: 켜짐이면 채운 스타일(캡처의 흰 테두리 = 켜짐).
- 🎨: 6색 팝오버. 목록·캔버스 노드 띠에 같이 반영.
- 정렬 `흐름 순`: START부터 BFS 순서(캡처의 video43-3 → 44 → 45처럼 이야기 순). `이름`, `최근 수정` 선택 가능.
- 행 드래그로 순서 바꾸기 없음 — 순서는 흐름이 결정한다.
- 흐름 탭과 선택 동기화: 행을 펼치면 캔버스 선택도 그 노드.

## 6. 동작 규칙

### 6-1. 새 비디오 등록
1. 파일 선택/드롭(여러 개 가능). 허용: `video/webm`, `video/mp4`, `image/webp`, `image/jpeg`, `image/png`. 한도: 영상 500MB, 이미지 20MB (작품 `theme` 성능 예산이 더 작으면 경고).
2. 브라우저에서 메타데이터 읽기: 길이, 해상도. 영상은 1초 지점 프레임을 캔버스로 떠서 포스터 WebP 생성.
3. 업로드(§7) — 행에 진행률 막대. 실패 시 행 유지 + `다시 시도`.
4. 새 노드 생성: `id` = 파일명 슬러그(중복이면 `-2`), `type: 'branch'`, `title.ko` = 파일명, `available: true`, `skippable: true`, `buttonShowBeforeEnd: min(5, 길이)`, 엣지 없음. 캔버스 위치: 흐름 탭에서 드롭했으면 그 좌표, 목록에서 등록했으면 마지막 노드 오른쪽.
5. 검사에 "도달 불가 노드" warn이 뜬다 — 정상. 연결하라는 안내.

### 6-2. 미디어 교체
같은 노드의 `media.src`만 바꾼다. 이전 파일은 게시본이 참조하는 동안 지우지 않는다(§7-3). 길이가 줄어 `buttonShowBeforeEnd`·숨은 링크 시간창·자막이 넘치면 검사 오류.

### 6-3. 복사
노드를 깊은 복사: 새 `id`(`원본-copy`, 중복 시 번호), `title` 뒤 ` 사본`, **나가는 엣지는 복사(엣지 id 새로), 들어오는 엣지는 복사하지 않음**, 미디어 파일은 공유(같은 `src`). 캔버스 위치 +40,+40.

### 6-4. 삭제
- 들어오는 엣지가 없으면 즉시 삭제 + 토스트 `삭제했어요 [되돌리기]`.
- 들어오는 엣지가 있으면 확인 대화상자: "`hub`, `coffee`에서 이 장면으로 오는 선택지 3개도 함께 지웁니다." — 확인 시 엣지와 함께 삭제.
- `start` 노드는 삭제 불가(버튼 비활성 + 이유 툴팁). 먼저 다른 노드를 START로 지정.
- 파일은 즉시 지우지 않는다(§7-3).

### 6-5. 초안 · 게시 · 슬롯
- 모든 편집은 초안에 반영하고 800ms 디바운스로 저장. 탭 닫기 전 `pagehide` flush.
- 게시본과 초안이 다를 때만 `Update` 활성.
- 동시 편집 충돌: 게시·초안 쓰기에 ETag 조건부 저장. 409면 "다른 곳에서 바뀌었어요 — [내 초안 내보내기] [새로고침]".
- 슬롯 3개는 초안 스냅샷(이름 없음, 저장 시각 표시). 게시 이력은 최근 10개 자동 보관, 셸 메뉴 `이전 게시본 복원`.

## 7. 저장소 (`@iw/story-store`)

```ts
interface StoryAdapter {
  loadPublished(workId): Promise<{ story: Story; etag: string }>;
  loadDraft(workId): Promise<{ story: Story; etag: string } | null>;
  saveDraft(workId, story, etag): Promise<{ etag: string }>;       // 409 → ConflictError
  publish(workId, story, etag): Promise<{ etag: string; version: number }>;
  listVersions(workId): Promise<VersionInfo[]>;
  restoreVersion(workId, version): Promise<void>;
  saveSlot(workId, slot: 1|2|3, story): Promise<void>;
  loadSlot(workId, slot): Promise<Story | null>;
  upload(workId, file, onProgress): Promise<{ src: string; bytes: number }>;
  gc(workId): Promise<{ removed: number }>;                         // §7-3
}
```

### 7-1. `local` 어댑터
IndexedDB `iw-story:<workId>`에 초안·슬롯·게시본·Blob. 업로드 결과 `src`는 `idb://<hash>` → 플레이어의 미디어 로더가 Blob URL로 해석. 게시 = 로컬 게시본 갱신(로컬 미리보기용). 배포 반영은 `JSON 내보내기 + 파일 묶음 zip` → 저장소 커밋.

### 7-2. `hub` 어댑터 (JUHO LAB Worker 확장)
허브 `server/index.js`에 작품 단위 API 추가. 기존 소유자 검사(`isOwner` + same-origin `Origin`)를 재사용.

| 메서드 · 경로 | 동작 |
|---|---|
| `GET /api/works/:id/story` | 게시본. 없으면 404 → 플레이어는 번들된 `story.json` 사용 |
| `GET·PUT /api/works/:id/draft` | 초안 (소유자) · `If-Match` |
| `POST /api/works/:id/publish` | 초안 검증(`lint`) 후 게시본 교체 + `versions/<n>.json` 보관 |
| `GET /api/works/:id/versions` · `POST …/versions/:n/restore` | 이력 |
| `PUT /api/works/:id/slots/:n` · `GET` | 슬롯 |
| `POST /api/works/:id/uploads` | R2 **멀티파트 업로드** 시작 → `PUT …/uploads/:uploadId/parts/:n` → `POST …/complete`. 파트 10MB |
| `GET /api/works/:id/media/:file` | R2 스트리밍, `Range` 지원(영상 탐색), `immutable` 캐시 |

R2 키: `works/<id>/story.json`, `works/<id>/draft.json`, `works/<id>/versions/<n>.json`, `works/<id>/slots/<n>.json`, `works/<id>/media/<uuid>.<ext>`.

- 플레이어 로드 순서: `/api/works/:id/story` → 실패 시 번들 `story.json`. 정적 배포(허브 밖)에서도 작품이 돈다.
- 서버도 `@iw/story-schema`의 zod + `lint`로 재검증. 클라이언트 검증을 신뢰하지 않는다.
- 파일 형식은 매직 바이트로 확인(확장자·MIME 헤더만 믿지 않음). SVG 거부 유지.

### 7-3. 파일 정리 (gc)
삭제·교체된 파일은 바로 지우지 않는다. `gc`는 **게시본 + 최근 게시 이력 10개 + 초안 + 슬롯 3개** 어디에도 참조되지 않는 `media/*`만 지운다. 관리 셸 메뉴 `사용하지 않는 파일 정리 (N개 · 120MB)`로 수동 실행.

## 8. 성능 · 접근성

- 관람 번들: `@iw/story-editor`·React Flow·dagre 0바이트. dawn-store `check-budget`를 **초기 로드 청크**와 **편집기 청크**로 나눠 측정 (편집기 청크 한도 250KB gzip).
- 캔버스 노드 200개에서 팬·줌 60fps 목표. 썸네일은 포스터 이미지만 로드, 영상 호버 재생은 동시 1개.
- 키보드: 캔버스 노드는 방향키로 이동 선택, `Enter`로 인스펙터. 목록은 표준 폼 컨트롤. 모든 아이콘 버튼에 이름. 색 태그는 색만으로 구분하지 않도록 이름 툴팁.

## 9. 보안

- 편집 API는 전부 소유자 전용 + same-origin. 읽기(`story`, `media`)만 공개.
- `ADMIN_MODE=auth`가 납품 기본. 편집기 청크는 인증 확인 후에만 요청(`docs/03` §6-3 "게이트는 하나").
- 사용자 입력 텍스트는 `textContent`로만 렌더. 엣지 라벨·메모도 동일.
- 업로드 크기·형식·파트 수 서버 측 제한, 멀티파트 미완료 업로드는 24시간 뒤 중단(abort).

## 10. 적용 순서

| 단계 | 내용 | 완료 기준 |
|---|---|---|
| 1 | `@iw/story-schema` 추출 — dawn-store가 이 패키지를 import하도록 교체, `lint-graph` CLI도 패키지 사용 | dawn-store `check:all` 그대로 통과 |

| 3 | `@iw/story-editor` 미디어 탭 (등록·복사·Skip·숫자·색·삭제·Update) | dawn-store `?edit=1`에서 로컬로 영상 추가→게시→재생 |
| 4 | 흐름 탭 (캔버스·Tab/Enter·엣지·인스펙터·검사·재생 추적) | 캔버스만으로 새 장면 연결해 재생 |
| 5 | `hub` 어댑터 + 허브 Worker API (보안 리뷰 포함) | 허브에 배포된 dawn-store에서 소유자가 영상 업로드·게시, 비소유자 403 |
| 6 | dawn-store 기존 `customization`(브라우저 로컬 작품 편집)을 초안 모델로 흡수. **2026-09-23 개정**: `meta`·`images`만 이야기 초안으로 가고, `colors`·`font`·`layout`·`audio`는 레이어 값으로 간다(`docs/11` §9-3). 편집기 셸 탭은 `[흐름] [미디어] [레이어]` | 설정 패널 `작품 편집` → 편집기 진입 한 곳으로 통일 |
| 7 | 두 번째 분기형 작품에서 코드 수정 없이 장면 추가 검증 | `docs/05` 패밀리 B 템플릿 갱신 |

**선행 조건**: 1·6단계는 dawn-store 코드를 바꾼다. 현재 다른 세션이 dawn-store(`customization.ts`, `CinematicPrelude.tsx` 등)를 미커밋 상태로 작업 중이다 — 그 작업이 커밋·머지된 뒤 시작한다.
