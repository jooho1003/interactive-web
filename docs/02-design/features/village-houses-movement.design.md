# Village houses and movement · Design

작성: 2026-10-05 · [Plan](../../01-plan/features/village-houses-movement.plan.md)

## Context Anchor
WHY: 실제 집8채·한 칸 드래그 해결. WHO: 동네 방문자. RISK: 그림 접합/입력 충돌. SUCCESS: 독립 집9채·거리 이동/복구 검증. SCOPE: 그림·매니페스트·카메라와 QA.

## 1. Architecture
A(최소 변경): 기존 확장 구조에 선비 패널 하나를 더하고 pointerup 한 칸 선택을 거리 기반 위치 유지로 바꾼다. B(새 월드): 개별 건물 모델·새 엔진, 요구보다 범위가 크다. C(전면 패널 교체): 기존 그림과 클릭 좌표까지 바꾸므로 회귀 위험이 크다. A를 선택한다.

## 2. Data and rendering
선비 x=33, 지붕 top=.14, 입구 bottom=.76, 클릭폭4.2. 새 패널 중심34.85·폭/높이12.096으로 기존 패널 오른쪽과 겹친다. 생성 결과의 실제 문 중심 약35%와 지붕 높이14%에 좌표를 맞췄다. 두 패널의 투영/최대 월드 경계는 매니페스트 현재값으로 계산한다. 선비/탑 이름표를 번갈아 숨기는 조건은 제거한다.

## 3. Input and state
pointerdown에 실제 카메라 x를 저장한다. 수평 pointermove는 시작 카메라 x에서 픽셀 이동을 월드 거리로 환산해 이동한다. pointerup은 경계 안의 최종 목표를 계산하고 가장 가까운 작품의 번호/설명을 선택한 뒤 목표 좌표를 유지한다. 경계는 그림의 끝과 첫/마지막 집 중심 중 안쪽 값으로 제한해 마지막 집을 지나 빈 정원만 보이지 않게 한다. 작은 클릭과 세로 제스처는 기존대로 둔다. 취소는 offset을 지우며 번호/키보드 선택은 작품 좌표로 이동한다.

## 4. Validation
집 좌표 중복 회귀 검사를 앱 validate에 넣는다. Aside 실제 화면에서 선비 집·POTATO 접합·길게 드래그·복귀를 확인한다. 데스크톱과 모바일에서 거리 유지/여러 칸 이동·끝 경계·키보드·입장 취소·동작 줄이기를 브라우저에서 검사한다. 두 host의 모든 파라미터를 기존 probe 방식으로 검증한다.

## 레이어 계약
Plan의 기존 house9개와 확장2개의 계약을 따른다. 신규 패널 이미지/위치/크기/밝기/블렌드는 설정에 노출하며 CSS/JS는 현재 host 값을 사용한다. 고정 좌표 투영과 이벤트 임계값은 manifest fixed에서 이유를 기록한다.
