## 1. 제작 철학 — 왜 "툴"을 만드는가

### 1-1. 일회용 프롬프트는 끝이 없다
> "매번 프롬프트로 '게임 움직이게 해줘' 이렇게 수정하면 그게 끝이 없거든요. 일회용밖에 안 되잖아요. 게임 만드는 툴을 만드는 접근이 더 나아요." (10:44)

- 처음엔 마리오 같은 RPG 하나를 만들려 했으나, 만들다 보니 **게임을 만드는 툴**이 됐다.
- 기능은 필요할 때 하나씩 얹는다: 캐릭터 이동 → NPC 대화 → 관리자 탭에서 대사 직접 타이핑 → 기즈모로 크기 조절 → 맵 추가 기능.

### 1-2. 첫 프롬프트에 반드시 넣는 조건
> "이 사이트는 내가 관리자로 직접 수정할 수 있는 기능이 되게 중요해. 너가 만드는 기능들이 관리자 탭에서 조작이 다 가능하게 하고, 예를 들어 메뉴를 네가 만들면 그 메뉴의 디자인을 내가 관리자 디자인 탭에서 수정할 수 있게 해줘." (28:34)

- **툴 + 관리자 페이지를 동시에 연동**시켜 놓는다.
- 마음에 안 드는 부분은 관리자에서 고치고, 관리자에 컨트롤이 없을 때만 프롬프트로 돌아간다.
- 이때 프롬프트도 명령이 아니라 상의: "슬라이더로는 안 된다. 솔루션은 네가 뭐라고 생각해? 이미지 교체 기능도 넣어줘."

### 1-3. 복제 → 확장
> "플랫폼 형식으로 만드는 게 나중에 재활용에 되게 좋아서, 다른 프로젝트를 할 때 그 프로젝트를 복제해서 중간 이미 만들어진 상태에서 시작하는 거예요." (29:23)

- 8개 예제는 8개의 다른 스타일이 아니라 **3개 베이스 그룹의 파생**이었다.
- 포트폴리오 사이트(로드맵) → 클라이언트 게임 의뢰 → 복제 후 게임 기능만 추가.
- 이것이 동시에 8개를 굴릴 수 있었던 이유.

### 1-4. 딸깍으로 나오지 않는다
> "계속 깎아야 돼요. 결과 나온 거 테스트, 추가, 테스트… 이게 되게 길어요. 그래서 결국에는 자기에 맞는 딱 그게 만들어지는 거죠." (29:23)

- 한 방에 나오는 작품은 울림을 주기 어렵다. 디렉팅으로 계속 디벨롭하는 능력이 핵심.

## 2. 워크플로우 — 이미지 한 장에서 3D 공간까지

### 2-1. 스타일 프레임 → 분해
1. Flora에서 **스타일 프레임**(룩이 정해진 장면 한 장)을 만든다.
2. 배경을 통째로 3D 변환하면 깨진다. **파트로 나눈다**: 바닥면 / 벽면 / 중요한 레이어(모니터 등) / 캐릭터 / 소품.
3. 예시: 강연장을 3D로 만든다면 → "의자+사람" 캐릭터 하나, 테이블은 별도 엘리먼트, 그 다음 바닥·벽.

### 2-2. 프랍 시트 프롬프트 (핵심 노하우)
> "이 스타일 프레임 이미지를 주면서 '여기에 있는 사람을 제외한 이런 오브젝트들을 4×4 그리드 안에다가 다 나눠서 넣어줘'라고 해요." (31:41)

- 한 장에 16개 오브젝트가 **통일된 스타일**로 생성된다.
- Flora의 자동 자르기 → 16개 개별 이미지로 저장.
- 메인 캐릭터는 그리드에 넣지 않고 **단독 한 장**으로 만든다.

### 2-3. 3D 변환 — Tripo
- 16장을 **동시에** 던져서 동시에 생성·저장.
- Tripo를 쓰는 이유: **로우 폴리곤**을 가장 잘 뽑는다. 웹 브라우징에서 가벼워야 하기 때문.
- "스마트 메시": 로우 폴리곤인데 텍스처는 디테일한 형태가 이상적.

### 2-4. 바이브 코딩으로 공간 조립
프롬프트가 진화한 순서 (그대로 따라 하면 된다):
1. "3D 파일을 올릴 수 있는 공간을 만들어줘" → 파일 찾기 버튼 하나
2. "이거 불편해, 드래그 드롭으로 해줘" → 하나만 됨
3. "여러 개도 되게 해줘" → 멀티 드래그
4. "동시에 여러 개 선택해서 크기 조절도 되게 해줘" → 비슷한 것끼리 묶어 일괄 조절

### 2-5. 페이스 트래킹 (오프-액시스 프로젝션)
- 카메라로 얼굴 위치를 추적해 3D 뷰 카메라를 움직인다 → 창문이 뚫린 것처럼 보인다.
- 제약: **앵글에 얼굴이 2명 이상 있으면 안 된다.**
- 카메라 + 3D 씬이 동시에 돌기 때문에 **데이터가 무거우면 끊긴다.** 가볍게 만드는 게 최우선.

### 2-6. 다음 세대 — 가우시안 스플래팅
- 메시 대신 이미지 조각으로 영상처럼 베이크된 고품질 씬.
- 현재 방식: AI 이미지 1장 → "너는 드론이고 한 바퀴 돌아봐" 영상 생성 → 프레임 분해 → 스플랫 생성.
- 문제: AI 영상은 한 바퀴 돌면 데이터가 달라진다. 점점 좋아질 것.
- 캐릭터 일관성 보완책: 스플랫 영상을 인풋으로 **video-to-video** 재생성.

- Kling 2개 + Seedance 2개 돌린다.

### 3-3. 플랫폼
- **Flora** (노드 방식): 채팅형은 위로 올라가며 사라지지만 노드는 오른쪽이 최신이라 관리가 쉽다.
  - 배치 노드: 이미지 100장 × 프롬프트 1개 = 100회 자동 실행.
  - 프롬프트 베리에이션 10개 생성 → 쪼개기 → 배치로 묶기 → 텍스트 10 × 이미지 10 = 100 베리에이션.
- 한 플랫폼에서 모든 모델을 쓰는 이유: 구독이 너무 많다. 새 모델이 나오면 플랫폼이 업데이트한다.
- **Tripo**: 로우폴리 3D. 배치 업로드.
- **Replit**: 클라우드라 핸드폰으로도 작업 가능. 멀티태스크 기능. (Claude Code는 내 컴퓨터가 켜져 있어야 함)
- **음성 입력** (Willow 등): 프롬프트는 말로 길게 설명한다.

## 4. 프롬프트 작성 요령

### 4-1. 초기 프롬프트 — 얼마나 자세히?
- **이미 있는 것을 캡처해서 보여준다.** "노션을 말로 설명하기 빡세니까 노션 페이지를 캡처해서, 이런 구성으로 갈 건데 내 기능은 여기에 레퍼런스 넣는 기능을 추가할 거야."
- 이미지 레퍼런스는 "**참고만 해**, 따라 하라는 게 아니라 이런 느낌이야"를 명시.
- 보이스 켜고 **토론하듯 길게** 말한다. 좋은 모델(Fable, Astra 등)은 간단히 말해도 잘 풀지만, 어느 정도를 원하는지는 말해야 한다.

### 4-2. 프롬프트 골격 (강연 내용을 템플릿화)
```
[레퍼런스] 첨부한 캡처는 구성 참고용이다. 그대로 따라 하지 말고 이런 느낌으로.
[목표] ~~를 체험할 수 있는 웹을 만든다.
[관리자] 네가 만드는 모든 기능은 관리자 탭에서 조작 가능해야 한다.
        메뉴를 만들면 그 메뉴의 디자인도 관리자 디자인 탭에서 수정할 수 있게 해라.
[성능] 웹에서 돌아야 하므로 가볍게. (3D면 로우폴리, 영상이면 스트리밍)
[첫 기능] 우선 ~~부터. 나머지는 테스트 후 추가한다.
```

## 5. 작업 방식

- **동시 3~4개 프로젝트**: 프롬프트 후 업데이트 기다리는 동안 다른 탭에서 다른 프로젝트.
- 헬스장 세트 사이, 바비큐 굽는 사이에도 클라우드로 진행.
- **R&D는 직장을 다녀도 계속**: 회사에서 "3D로 만들자"고 논의 중일 때 가우시안 스플랫으로 보여주면 입지가 바뀐다.
- **인스퍼레이션 저장 → 프로젝트 시작 전마다 리뷰**: 저장만 하고 안 보는 걸 억지로라도 돌려본다.
- 노트는 Obsidian → Notion으로 이전. 기술적인 건 안 적고 **생각·경험·감명**을 적는다. 바이브 코딩이 좋아져서 기술 노트 필요성이 줄었다.

## 6. 포지셔닝 — 왜 이 조합인가

> "AI 영상 커뮤니티에 가면 다 영화 만들고, 바이브 코딩 커뮤니티에 가면 다 웹사이트 만들어요. 근데 이거를 섞는 사람이 많이 없어요." (08:09)

- 바이브 코딩 쪽에서는 "비주얼이 특이하다", AI 영상 쪽에서는 "인터랙션이 된다"고 신기해한다.
- 이 포트폴리오로 각 회사 본사에 연락 → 앰버서더 계약 → 무료 사용 + 세미나·웨비나 기회.
- AI로 만든 티를 굳이 밝히지 않는다. 3컷 중 중간에 AI 컷을 적재적소에 섞는다. 색안경이 있다.
- 실무에선 AE 키프레임 대신 **프로시저럴 스크립트**를 바이브 코딩으로 만든다 (카드 셔플: A~E 포인터 + 타이밍 슬라이더 → 클라이언트 수정 요청 시 포인트만 바꾸면 끝).
- 쉬워지면 다 쉬워진다 → 믹스한 콘텐츠, 스토리, 과정 자체를 작품으로 포장하는 능력이 차별점.
