# 11. 레이어 설정 시스템 설계 (`@iw/layer-kit`)

작성 2026-09-23. 대상은 이 저장소의 **모든 인터랙티브**다. 이미 있는 작품(dawn-store·day-walk·potato-designer)과 허브(jooho-lab), 그리고 앞으로 만들 작품이 모두 포함된다.
플랜: [`.claude/plans/layer-system-2026-09-23.md`](../.claude/plans/layer-system-2026-09-23.md)

**구현 상태 (2026-09-23)**: Potato Designer에 공용 값/런타임·생성기·lint/probe와 Scene Studio를 적용했다. 20개 레이어, 619개 파라미터의 실제 렌더링 검사 통과. 이번 범위의 확정 UX·로컬 게시/인증 경계·미구현 DSL 및 다른 앱 이관은 [12번 구현 설계](12-Scene-Studio-관리자-설계.md)와 [검수 기록](../projects/potato-designer/QA.md)을 따른다. 아래 내용은 네 앱을 향한 전체 설계이며 전 항목이 구현 완료된 상태는 아니다.

## 0. 왜 다시 설계하나

> "인터랙티브의 진행을 할 때, 각 레이어별로 이제 설정해서 다 컨트롤할 수 있게끔 만들어 달라고 했는데, 방금 만든 포테이토에는 그런 기능이 없는 것 같네. 모든 인터랙티브 여기서 작업하는 것들은 다 그런 레이어를 나눠가지고 설정해서 다 변경할 수 있게 해야 돼." (사용자, 2026-09-23)

이 요구는 전에도 있었다. [`docs/03`](03-모노레포-설계.md)의 §3-1 `config-schema`, §3-2 `core-admin`, §3-3 `inline-editor`와 개발 규칙 7("화면에 보이는 값은 툴바로 고칠 수 있어야 한다")이 그 결과물이다. 그런데 **문서로만 남고 구현되지 않았다.** 그 사이 앱 네 개가 각자 다른 방식으로 설정을 만들었고, 레이어 단위로 나눈 곳은 하나도 없다.

| 앱 | 현재 설정 방식 | 레이어로 보면 빠진 것 |
|---|---|---|
| potato-designer | **없음.** 장면 3개(`app.js` `scenes`), 포인터 강도 22·13·6·9, 위치·크기·모션 시간이 CSS와 JS에 하드코딩. 반응형 3단계가 모든 수치를 다시 하드코딩 | 전부 |
| dawn-store | `customization.ts`: 색 8·글꼴·배치 8·BGM, 평면 필드셋. `theme.json`은 요소별 섹션(arrow·menu·subtitle…)과 `zIndex` 표를 이미 가짐 | 화살표·메뉴·질문 크기, 전환 시간, 핫스팟, 효과음, 영상 노드, 도입부(`CinematicPrelude`는 하드코딩) |
| day-walk | 설정 대화상자에 캐릭터·새 보이기 체크박스 2개 | 배경 3장·보행자·깃발·HUD의 크기·위치·색·전환 |
| jooho-lab | 소유자 편집기(문구·그림·캐릭터·공간 4섹션) → R2. 가장 앞서 있음 | 집 6채 좌표, 조명 색(`village-motion.js`), 파노라마, UI 오버레이 |

원인은 두 가지다. ① 요구가 대화에만 있고 저장소 규칙(`AGENTS.md`)에는 없었다. ② "빠짐없이 바꿀 수 있는가"를 확인하는 **검사**가 없었다. 규칙 7은 스냅샷 테스트를 약속했지만 그 테스트를 만든 적이 없다. 그래서 이 설계는 기능(§4~§7)과 함께 **강제 장치**(§8)를 계약에 포함한다.

potato 기능 확장 플랜(`potato-functional-learning-2026-09-23`)은 "관리자·공용 패키지는 두 번째 소비자가 없어서 보류"라고 적었다. 이번 요구로 그 보류를 뒤집는다. 레이어 설정은 이제 **네 앱 전부가 소비자**이므로, `docs/03` §0-4의 패키지 추출 트리거("두 번째 소비자")도 이미 충족됐다.

이 문서는 시각 레이어에 대해 `docs/03` §3-1~§3-3을 대체하는 구체안이고, `docs/03` §8의 4단계 "편집 계약 통일"을 실제로 수행하는 설계다. 이야기 그래프와 미디어는 [`docs/09`](09-흐름-에디터-미디어-관리-설계.md)가 계속 맡는다(경계는 §9-3).

## 1. 계약

**한 줄 계약.** 화면에 보이는 모든 층은 레이어 목록에 나온다. 각 층의 조정 가능한 값(보임, 위치, 크기, 색, 문구, 이미지, 모션, 입력 반응 강도)은 설정 패널에서 바꿀 수 있다. 그 값은 장면(진행 단계)별로, 화면 크기별로 따로 줄 수 있다. 코드에 남는 것은 구조뿐이다.

| # | 요구 | 확인 방법 |
|---|---|---|
| R1 | 레이어 목록: 모든 시각 요소가 어느 한 레이어에 속한다 | `layer-lint` §8-1 규칙 2 |
| R2 | 레이어마다 보이기/숨기기와 불투명도 | 표준 특성 `visible` |
| R3 | 조정할 수 있는 수치·색·문구·이미지·모션이 CSS·JS에 리터럴로 남지 않는다 | `layer-lint` 규칙 4 |
| R4 | **진행**: 장면마다 레이어 값을 덮어쓰고, 장면 사이 전환 시간·곡선을 설정한다. 시간·스크롤·진행률 같은 연속 진행에 반응하는 강도도 설정한다 | §4-5, §5-3 |
| R5 | 화면 크기별 값 (최소 데스크톱/모바일, 앱이 선언한 만큼) | §4-5 |
| R6 | 바꾼 값이 즉시 보이고, 되돌리고, 파일로 내보내고, 게시할 수 있다 | §6, §7 |
| R7 | 값 하나하나가 실제로 화면을 바꾼다 (죽은 컨트롤 없음) | `layer-probe` §8-2 |
| R8 | 관람자 번들 부담은 최소 (편집기는 동적 로드) | §5-6 예산 |

### 하지 않는 것 (1단계)
- 키프레임 타임라인 편집기(시간축에 값을 찍는 애니메이션 에디터). 장면 전환과 입력 반응으로 먼저 충분한지 확인한다(§13).
- 레이어 추가·삭제를 패널에서 하기. 레이어는 코드가 선언한다(§3 결정 D4). 패널은 선언된 레이어의 값을 바꾼다.
- 목록형 데이터 편집. potato 작업 카드, dawn-store 이야기 노드, 허브 작품 목록은 레이어가 아니다(결정 D1).
- 여러 사람이 동시에 편집하기.

## 2. 용어

| 용어 | 뜻 | potato 예 |
|---|---|---|
| **레이어** | 화면의 시각적 층 하나. 고유 id, 이름, 그룹, 대상 요소(또는 캔버스 객체)를 가진다 | `character` 캐릭터, `ticker` 흐르는 띠 |
| **파라미터** | 레이어의 조정 가능한 값 하나. 타입, 범위, 기본값, 바인딩을 가진다 | `character.pointer.x` = 22px |
| **특성(trait)** | 파라미터 묶음 표준. 이름·범위·CSS 변수 규칙이 정해져 있다 | `visible`, `box`, `enter`, `loop`, `pointer` |
| **장면(scene)** | 진행 단계. 레이어 값 덮어쓰기 묶음과 전환 설정 | `brand` / `digital` / `character` |
| **화면(breakpoint)** | 앱이 선언한 미디어 쿼리 구간 | `wide` ≥1600, `tablet` ≤1000, `mobile` ≤650 |
| **입력(input)** | 앱이 매 프레임 넘기는 원시값(-1~1, 0~1) | `pointer.x`, `pointer.y` |
| **범위(scope)** | 값을 어디에 쓰는가 = 장면 × 화면 | "digital 장면 · 모바일" |
| **매니페스트** | 레이어·파라미터·장면·화면 선언. 코드이며 개발자가 소유한다 | `layers.manifest.js` |
| **값 파일** | 매니페스트 기본값에 덮어쓰는 차이만 담는다. 데이터이며 편집자가 소유한다 | `layers.values.json` |
| **초안** | 게시 전 편집값. 편집한 브라우저에 저장된다 | `localStorage iw-layers:potato-designer:draft` |

## 3. 핵심 결정

| # | 결정 | 대안 | 이유 |
|---|---|---|---|
| D1 | **레이어 = 화면의 시각적 층.** 목록형 데이터(작업 카드, 이야기 노드, 작품 목록)는 레이어가 아니다. 레이어가 그 목록을 *어떻게 보여 주는지*(카드 색, 간격, 호버)만 파라미터가 된다 | 모든 데이터를 레이어로 | 목록 편집은 행 추가·삭제·순서가 핵심이라 UI가 다르다(`docs/09` 흐름 에디터, 허브 콘텐츠 편집기). 한 도구에 섞으면 둘 다 나빠진다 |
| D2 | 공용 패키지 하나 `@iw/layer-kit`. **의존성 없는 순수 JS ES 모듈에 `.d.ts` 타입을 붙인다** | zod + TS 소스 패키지(`docs/09` D7 방식) | 소비자 넷 중 둘(potato, jooho-lab)은 빌드 없는 정적 사이트다. 빌드를 새로 들이지 않으려면 브라우저가 바로 읽는 JS여야 한다. 검증은 파라미터 정의(min·max·enum·pattern)가 한다. zod가 하던 일을 선언 데이터가 대신한다 |
| D3 | 정적 앱은 **벤더 복사**(`layer-kit vendor`), Vite 앱은 워크스페이스 import | 정적 앱에 Vite 도입 | jooho-lab이 three.js를 벤더링하는 방식과 같다. `check`가 복사본 해시를 대조한다 |
| D4 | **구조와 값을 분리한다.** 레이어·파라미터 선언은 매니페스트(코드)에 둔다. 편집값은 값 파일(데이터)에 **기본값과의 차이만** 둔다 | 전체 값을 덤프 | 매니페스트에 파라미터를 추가해도 기존 값 파일이 깨지지 않는다. 값 파일의 차이가 곧 패널의 "변경 목록"이다 |
| D5 | 수치·색·토글은 **CSS 변수**로 흐른다. JS는 입력의 원시값(`--in-pointer-x` 등)만 쓴다. 강도 × 입력은 CSS `calc()`가 계산한다 | JS가 transform 문자열을 계산 | potato·dawn-store가 이미 CSS 변수 구조다. JS에 남던 매직 넘버(22, 13, 6, 9)가 사라지고 전부 파라미터가 된다 |
| D6 | 첫 페인트는 **생성 CSS**(`layers.css`)가 책임진다. 기본값과 게시값을 모든 화면 × 장면 조합으로 구워 둔다 | 런타임 JS만 사용 | JS가 실행되기 전에도 정확한 모습이 나오고 깜빡임이 없다. 생성기와 런타임이 같은 `resolve()`를 쓰므로 결과가 갈리지 않는다 |
| D7 | **진행 = 장면.** 장면은 레이어 값 덮어쓰기 묶음과 전환 시간·곡선이다. *언제* 장면을 바꿀지는 앱이 정한다(`host.setScene`) | 킷이 진행을 소유 | 진행 방식이 앱마다 다르다(버튼, 이야기 그래프, 시각). 킷은 "무엇이 보이나"를, 앱은 "언제 바뀌나"를 맡는다 |
| D8 | 연속 진행(시각·스크롤·재생 위치)은 **입력 변수**로 받는다. 파라미터는 반응 강도·범위를 가진다 | 키프레임 에디터 | 1단계 범위를 줄인다. day-walk의 하루 진행, potato의 포인터 모두 이것으로 된다 |
| D9 | 해석 순서를 고정한다: **기본 → 화면 → 장면 → 장면×화면 → 관람자**. 같은 범위 안에서는 값 파일이 매니페스트를 이긴다 | 앱마다 다르게 | 생성 CSS의 명시도 순서와 일치시켜 JS와 CSS 결과가 같아지게 한다(§4-5) |
| D10 | 편집 패널은 **하나**다(Shadow DOM 웹 컴포넌트). 편집 모드에서만 동적 import한다 | 앱마다 패널 | React 앱과 바닐라 앱 모두 마운트할 수 있다. 작품 CSS와 스타일이 서로 새지 않는다. 관람자가 받는 번들은 0바이트다 |
| D11 | 1단계 게시 = 값 파일 내보내기 → `layer-kit apply` → 커밋·배포. 서버 게시는 허브 소유자 경로만 둔다(L8b) | 모든 앱에 서버 저장 | 정적 앱에는 백엔드가 없다. 보안 표면을 허브 하나로 모은다 |
| D12 | "빠짐없이"는 문서 규칙이 아니라 **검사**로 강제한다. `layer-lint`(정적)와 `layer-probe`(브라우저)를 각 앱 `check`에 넣는다 | 문서 규칙만 | 규칙 7이 문서에만 있어서 지켜지지 않았다. potato가 그 증거다 |
| D13 | 초안은 편집한 브라우저에서 **항상 적용**하고 배지를 띄운다. 패널에 "게시본으로 보기" 토글을 둔다 | 편집 모드에서만 적용 | 편집 모드를 닫았을 때 "고친 게 사라졌다"고 오해하지 않게 한다. 초안은 그 브라우저에만 있으니 다른 관람자에게는 영향이 없다 |

## 4. 데이터 모델

### 4-1. 매니페스트 (`layers.manifest.js`)

```js
// potato-designer/dist/layers.manifest.js (발췌)
import { defineLayers, p, traits } from './vendor/layer-kit/index.js';

export default defineLayers({
  work: 'potato-designer',
  version: 1,                                   // 파라미터 이름을 바꾸면 올리고 migrate를 붙인다 (§4-7)
  breakpoints: [                                // 뒤쪽이 우선. 아무것도 안 맞으면 '데스크톱'(기본)
    { id: 'wide',   label: '와이드', media: '(min-width: 1600px)' },
    { id: 'tablet', label: '태블릿', media: '(max-width: 1000px)' },
    { id: 'mobile', label: '모바일', media: '(max-width: 650px)' },
  ],
  inputs: ['pointer'],                          // host가 --in-pointer-x/y 를 쓴다
  fonts: [                                      // 글꼴은 이 목록에서만 고른다 (docs/03 §3-3-4)
    { id: 'barlow', label: 'Barlow Condensed', stack: "'Barlow Condensed', Impact, sans-serif" },
    { id: 'dm',     label: 'DM Sans',          stack: "'DM Sans', Arial, sans-serif" },
  ],
  initialScene: 'brand',
  scenes: {
    brand:     { label: 'Brand Design',       transition: { ms: 700, ease: 'ease' },
                 set: { paper: { color: '#e9ebe8' }, global: { accent: '#cb443c' }, character: { rotate: -5,  zoom: 1 },    word: { text: 'PLAY' } } },
    digital:   { label: 'Digital Experience', transition: { ms: 700, ease: 'ease' },
                 set: { paper: { color: '#e0e6e9' }, global: { accent: '#4365b4' }, character: { rotate: 3,   zoom: 0.94 }, word: { text: 'MOVE' } } },
    character: { label: 'Character Design',   transition: { ms: 700, ease: 'ease' },
                 set: { paper: { color: '#e8e9db' }, global: { accent: '#7b833c' }, character: { rotate: -10, zoom: 1.05 }, word: { text: 'HEY!' } } },
  },
  layers: [
    { id: 'character', label: '캐릭터', group: '무대', el: '.character-motion', params: {
      ...traits.visible(),
      src:         p.image('./assets/character.png', { label: '이미지', attr: ['img.character', 'src'] }),
      x:           p.pct(-8, { label: '가로 위치', min: -60, max: 60, at: { mobile: 0 } }),
      y:           p.pct(-5, { label: '세로 위치', min: -60, max: 60, at: { tablet: -3, mobile: 0 } }),
      width:       p.vw(77,  { label: '너비', min: 20, max: 140, at: { tablet: 90 } }),
      'max-width': p.px(1100, { label: '최대 너비', min: 300, max: 2400 }),
      rotate:      p.deg(-5, { label: '기울기', css: '--rz' }),           // 기존 변수 이름 유지
      zoom:        p.number(1, { label: '확대', css: '--zoom', min: 0.5, max: 2, step: 0.01 }),
      ...traits.enter({ ms: 1700, ease: 'cubic-bezier(.17,.7,.27,1)', from: { x: 15, y: -16, scale: 0.48, rotate: 15 } }),
      ...traits.loop('float', { ms: 7000, y: 18, rotate: 2 }),
      ...traits.pointer({ x: 22, y: 13, 'tilt-x': 6, 'tilt-y': 9, 'lag-ms': 120 }),
    }},
    // … §9-1 표의 나머지 레이어
  ],
  fixed: [                                      // 레이어 파라미터로 만들지 않는 값과 이유 (패널 '고정값' 탭에 표시)
    { selector: '.skip-link', reason: '접근성 건너뛰기 링크 — 구조' },
    { selector: 'button:focus-visible', reason: '포커스 표시 — 접근성 최소 기준, 색만 global.accent를 따름' },
  ],
});
```

**레이어 필드.** `id`(케밥, 작품 내 유일), `label`, `group`(패널 트리), `el`(대상 선택자; 캔버스·오디오 레이어는 생략), `kind`(`dom` 기본 · `canvas` · `three` · `audio` · `global`), `params`.

**파라미터 키.** `[a-z0-9-]+(\.[a-z0-9-]+)*` 형식이다. 점은 인스펙터에서 섹션을 나누는 데 쓴다(`pointer.x` → "포인터" 섹션). CSS 변수 이름은 `--L-<레이어>-<키의 점을 대시로>`가 기본이다(`--L-character-pointer-tilt-x`). 기존 앱의 변수를 살려야 하면 `css:`로 이름을 지정한다. 변수 이름이 겹치면 lint가 막는다.

### 4-2. 파라미터 타입

| 빌더 | 저장값 | 컨트롤 | 바인딩 기본 | 비고 |
|---|---|---|---|---|
| `p.number` | 수 | 슬라이더 + 숫자 입력 | CSS 변수(단위 없음) | `min`·`max` 필수, `step` |
| `p.px` `p.pct` `p.vw` `p.vh` `p.deg` `p.ms` | 수 | 슬라이더 + 숫자 + 단위 표시 | CSS 변수(단위 붙임) | 단위는 정의가 고정한다. 값에 단위 문자열을 넣지 않는다 |
| `p.color` | `#rrggbb` 또는 `#rrggbbaa` | 팔레트 → 저장색 → 자유 hex | CSS 변수 | 팔레트는 `global` 레이어의 색 파라미터 목록 |
| `p.toggle` | 불리언 | 스위치 | CSS 변수 `on`/`off` 키워드 쌍 | 예: `{ on: 'float', off: 'none' }` → `animation-name` |
| `p.select` | 목록 중 하나 | 선택 상자 | CSS 변수 | `options: [{ value, label }]` |
| `p.easing` | 프리셋 id 또는 `cubic-bezier(a,b,c,d)` | 프리셋 + 곡선 편집 | CSS 변수 | 네 수는 −2~3 범위 검증 |
| `p.font` | `fonts[].id` | 선택 상자 | CSS 변수(스택 문자열) | 매니페스트에 없는 글꼴 금지 |
| `p.text` | 문자열, 또는 `i18n`이면 `{ ko, en }` | 한 줄/여러 줄 입력, 언어 탭 | `text: '<선택자>'` → `textContent` | 줄바꿈은 `\n` + CSS `white-space: pre-line`. HTML 불가 |
| `p.image` | 에셋 경로 | 드롭존 + 미리보기 | `attr: [선택자, 'src']` 또는 CSS `url()` | §11 허용 목록 |
| `p.audio` | `{ src, volume, loop }` | 파일 + 볼륨 | `fn:` | dawn-store BGM·효과음 |

**바인딩 종류.** `css`(CSS 변수, 기본), `text`(선택자의 `textContent`), `attr`(선택자의 속성), `fn`(앱이 등록한 함수, 캔버스·three.js·오디오용)이 있다. 파라미터 하나에 바인딩을 여러 개 걸 수 있다. 예: `paper.color`는 CSS 변수와 `<meta name="theme-color">` 속성을 둘 다 바꾼다.

**파라미터 공통 옵션.** `label`, `hint`, `at`(화면별 기본값), `scene: false`(장면에서 못 바꿈), `responsive: false`(화면별로 못 바꿈), `viewer: true`(관람자 설정에 노출, §7).

### 4-3. 표준 특성

앱마다 이름을 새로 짓지 않게 자주 쓰는 묶음을 표준으로 둔다. 각 특성이 만드는 파라미터 키, 라벨, 범위, CSS 변수는 킷이 정한다.

| 특성 | 만드는 파라미터 | CSS에서 쓰는 법 |
|---|---|---|
| `traits.visible()` | `visible`(토글), `opacity`(0~1) | `visible: false`면 생성기가 `display:none!important` 규칙을 해당 범위에 굽는다. `opacity: var(--L-x-opacity)` |
| `traits.box({x,y,width,height,…})` | 위치·크기(단위는 옵션) | `left/top/width/height: var(--L-x-…)` |
| `traits.transform({rotate,scale})` | 회전·배율 | `transform` 안의 `var()` |
| `traits.enter({ms,ease,delay,from})` | `enter.on` `enter.ms` `enter.ease` `enter.delay` `enter.from-x/y/scale/rotate` | 등장 `@keyframes` 안에서 `var()` 사용. 패널의 "등장 다시"가 재생한다 |
| `traits.loop(name,{ms,…})` | `<name>.on` `<name>.ms` + 진폭 파라미터 | 반복 `@keyframes` 안에서 `var()`. `animation-duration: calc(var(--L-x-name-ms) / var(--L-global-speed))` |
| `traits.pointer({x,y,tilt-x,tilt-y,lag-ms})` | 포인터 반응 강도 | `calc(var(--in-pointer-x) * var(--L-x-pointer-x))` |
| `traits.progress({from,to,…})` | 진행률 구간과 대상 값 범위 | `calc(var(--L-x-from) + var(--in-progress) * (…))` |
| `traits.z()` | 그룹 안 쌓임 순서 | `z-index: var(--L-x-z)`. 패널의 드래그 정렬이 값을 쓴다 |
| `traits.type({font,size,weight,tracking,leading,color})` | 글자 모양 | `font-*`, `letter-spacing`, `line-height`, `color` |

`@keyframes` 안에서 쓴 CSS 변수는 애니메이션 대상 요소의 값으로 계산되므로, 진폭과 시작 위치도 파라미터로 만들 수 있다.

### 4-4. 값 파일 (`layers.values.json`)

매니페스트 기본값과 **다른 값만** 담는다. 초안(localStorage)과 게시본(파일)이 같은 형식을 쓴다.

```json
{
  "format": "iw-layers/1",
  "work": "potato-designer",
  "manifestVersion": 1,
  "updatedAt": "2026-09-23T10:42:00+09:00",
  "base":       { "character": { "pointer.x": 30 }, "ticker": { "visible": false } },
  "responsive": { "mobile": { "character": { "zoom": 0.9 } } },
  "scenes":     { "digital": { "base": { "paper": { "color": "#dde5ea" } }, "responsive": {} } },
  "order":      { "무대": ["ground-shadow", "character", "crosshairs"] }
}
```

- 장면 id와 화면 id는 매니페스트에 있는 것만 쓴다. 값 파일로 장면을 새로 만들 수 없다. 장면을 켜는 트리거가 앱 코드에 있기 때문이다(D7).
- 초안에는 `baseRevision`(편집을 시작할 때 게시본의 `updatedAt`)을 더 저장한다. 게시본이 그 뒤에 바뀌면 패널이 "게시본이 바뀌었어요 — [초안 유지] [게시본 기준으로 다시]"를 묻는다.

### 4-5. 해석 순서

파라미터 P를 화면 B, 장면 S에서 해석하면 다음 순서대로 덮어쓴다(뒤가 이긴다).

```
① 매니페스트 기본값             p.px(22)
② 값 파일 base                  base.character["pointer.x"]
③ 매니페스트 화면 기본값          at.tablet → at.mobile   (breakpoints 순서대로, 맞는 것 전부)
④ 값 파일 화면                  responsive.tablet → responsive.mobile
⑤ 매니페스트 장면 값             scenes.S.set
⑥ 값 파일 장면                  scenes.S.base
⑦ 값 파일 장면×화면              scenes.S.responsive.B
⑧ 관람자 설정 (viewer: true 파라미터만)
```

더 구체적인 범위가 이긴다. 같은 범위 안에서는 값 파일이 매니페스트를 이긴다. 예를 들어 편집자가 `character.x`를 모든 화면에서 −4로 바꿨다고 하자. 매니페스트에 `at: { mobile: 0 }`이 있으면 모바일에서는 계속 0이다. 패널은 모바일 화면에서 그 파라미터 옆에 `모바일 기본값이 덮는 중`을 표시하고 `모바일 값 지우기`를 제공한다. CSS 명시도와 같은 규칙이라 생성 CSS와 런타임 결과가 일치한다.

생성 CSS의 대응 관계는 다음과 같다. `:root{}`가 ①②이고, `@media … { :root{} }`가 ③④다(선언 순서로 뒤가 이김). `:root[data-scene=S]{}`가 ⑤⑥이고 속성 선택자 때문에 명시도가 더 높다. `@media … { :root[data-scene=S]{} }`가 ⑦이며, ⑧은 런타임 인라인 스타일이다.

### 4-6. CSS 변수 규칙

| 접두사 | 누가 쓰나 | 예 |
|---|---|---|
| `--L-<layer>-<key>` | 생성 CSS(게시값), 런타임(초안) | `--L-character-pointer-x: 22px` |
| `--in-<input>` | 런타임 입력 루프만 | `--in-pointer-x: -0.34` |
| `--L-global-*` | `global` 레이어 | `--L-global-speed: 1` |
| 기존 이름(`--paper`, `--accent`, `--rz`, `--zoom`) | `css:` 옵션으로 명시한 경우 | 마이그레이션 비용을 줄이려고 허용 |

CSS에는 `var()`만 남기고 폴백 리터럴(`var(--x, 22px)`)은 쓰지 않는다. 생성 CSS가 항상 모든 변수를 정의하므로 폴백은 두 번째 원천이 될 뿐이다. lint가 폴백을 금지한다.

### 4-7. 버전과 고아 값

- `manifestVersion`이 올라가면 매니페스트의 `migrate: { 2: (values) => … }`로 값 파일을 변환한다. 파라미터 이름 변경이 대표 사례다.
- 매니페스트에 없는 레이어나 파라미터를 가리키는 값은 **버리지 않는다.** 적용하지 않은 채 `orphans`로 보관하고, 패널 상단에 `알 수 없는 값 3개 [보기] [삭제]`를 띄운다(`docs/03` §3-3-3 "조용한 소실이 가장 나쁘다"). `layer-kit apply`는 고아가 있으면 경고하고, `--strict` 옵션이면 실패한다.

## 5. 런타임 (`host`)

### 5-1. API

```js
import manifest from './layers.manifest.js';
import published from './layers.values.js';        // 정적 앱: JSON을 모듈로 감싼 생성 파일 (추가 요청 없음)
import { createLayerHost } from './vendor/layer-kit/index.js';

const host = createLayerHost({
  manifest, published,
  root: document.documentElement,
  bindings: { setThemeColor: (v) => (document.querySelector('meta[name="theme-color"]').content = v) },
});
host.setScene('digital');                 // 진행 트리거는 앱이 부른다
host.input('pointer', { x, y });          // rAF로 묶어 --in-pointer-x/y 두 개만 쓴다
host.get('character', 'zoom');            // 해석된 현재값 (현재 화면·장면)
host.subscribe((change) => { … });        // 캔버스 앱이 fn 바인딩 대신 쓸 수도 있다
host.pause(true);                         // 입력 반응과 반복 모션 정지 (사용자 정지·패널 열림·탭 숨김)
if (host.editRequested) host.openEditor(); // ?edit=1 등 → import('./panel/index.js')
```

React 앱에는 얇은 훅을 둔다: `const host = useLayerHost(manifest, published)`, `const zoom = useLayer('character', 'zoom')`. 렌더에 값이 필요한 드문 경우(캔버스 크기 계산 등)에만 쓴다. 대부분은 CSS 변수로 끝난다.

### 5-2. 시작 순서

1. **첫 페인트**: 생성 `layers.css`가 기본값과 게시값을 모두 담고 있다. 텍스트와 이미지는 정적 앱이면 `layer-kit build --bake-html`이 HTML의 표시된 요소(`data-layer-text`, `data-layer-src`)에 미리 굽는다. JS 없이도 게시된 모습이 그대로 나온다.
2. **host 생성**: `data-scene` 초기값을 설정한다. 이미지·텍스트는 이미 구워져 있으니 다시 쓰지 않고, `fn` 바인딩만 한 번 호출한다.
3. **초안이 있으면**(D13): 현재 화면·장면에서 모든 CSS 파라미터를 해석해 `:root` 인라인 스타일로 쓰고, 텍스트·속성·fn을 적용한다. 화면(`matchMedia` change)이나 장면이 바뀌면 다시 해석한다. 우하단에 `초안 적용 중 · 편집` 배지를 띄운다.
4. **편집 요청이면**: 패널을 동적 import한다.

### 5-3. 장면 전환 (진행)

`setScene(S)`는 `:root`의 `data-scene`을 바꾼다. 수치·색 전환은 CSS `transition`이 맡는데, 그 시간과 곡선도 파라미터(`--L-scene-ms`, `--L-scene-ease`)다. 텍스트·속성·fn 바인딩은 host가 바로 적용한다. `transition.ms` 동안 텍스트를 교차 페이드할지는 레이어 옵션 `textSwap: 'fade' | 'cut'`로 정한다. 전환 중에 다시 호출되면 마지막 호출만 적용한다. `document.startViewTransition`은 쓰지 않는다. 포인터 입력과 충돌하고 브라우저 지원도 불균등하기 때문이다.

진행 방식별 예:

| 앱 | 진행 트리거 (앱 코드) | 킷에 넘기는 것 |
|---|---|---|
| potato | 분야 버튼, "메인 분위기 적용" | `setScene('digital')` |
| day-walk | 현재 시각 (분 단위) | `input('progress', xOf(minute))` + 구간이 바뀔 때 `setScene('afternoon')` |
| dawn-store | 이야기 노드 진입 | 노드의 `layerScene` 필드(선택) → `setScene`, 재생 위치 → `input('media', t/duration)` |
| jooho-lab | 공간/목록 보기, 선택한 집 | `setScene('list')`, `input('camera', …)` |

### 5-4. 입력

`inputs` 선언에 따라 host가 이벤트를 붙이거나 앱이 값을 넣는다. `pointer`는 host가 대상 요소에 `pointermove`를 붙이는 옵션을 제공하며, 터치는 무시하고 이탈하면 0으로 돌린다(potato의 현재 동작 그대로). `scroll`은 host가 계산할 수 있다. `progress`, `media`, `camera`는 앱이 넣는다. 쓰는 변수는 입력당 1~2개이고 rAF 한 번으로 묶는다. `pause(true)`이거나 동작 줄이기가 켜져 있으면 모든 입력을 0으로 고정한다.

### 5-5. 캔버스 · three.js 레이어

DOM이 없는 레이어(`kind: 'three' | 'canvas'`)는 `fn` 바인딩으로 앱 함수를 부른다. 예: `lights.color: p.color('#ffd27a', { fn: 'setLightColor' })`. 앱의 렌더 루프가 `host.get()`으로 읽어도 된다. 패널의 선택 모드(§6-4)가 캔버스 안 객체를 가리킬 수 있도록, 앱은 선택적으로 `bindings.pick(x, y) → layerId`와 `bindings.bounds(layerId) → DOMRect[]`를 제공한다. 제공하지 않으면 목록에서만 고를 수 있다.

### 5-6. 동작 줄이기 · 정지 · 예산

- `prefers-reduced-motion`: 생성 CSS가 모든 `enter`·`loop`를 끄고, 입력을 0으로 둔다. 패널에서 "동작 줄이기 흉내" 토글로 미리 볼 수 있다.
- 사용자 정지, 패널이나 대화상자 열림, 탭 숨김은 `host.pause`로 통일한다. 장면과 값은 유지한다. potato에서 "정지가 장면을 초기화하던 결함"(docs/10)을 구조적으로 막는다.
- **예산**: 런타임(index·define·values·host·inputs·storage)은 gzip 7KB 이하다. 패널은 동적 로드로 gzip 40KB 이하다. 생성 CSS는 앱당 gzip 12KB 이하다. 입력 반응은 프레임당 CSS 변수 쓰기 2~4개다.

### 6-2. 레이어 목록

- 그룹 트리다. 행마다 👁(보이기 토글, `visible` 파라미터를 현재 범위에 씀), 이름, 종류 아이콘, 수정됨 점(•)을 둔다.
- **솔로**(Alt+클릭 👁): 다른 레이어를 잠시 숨긴다. 저장하지 않는다. **잠금**: 선택 모드에서 이 레이어를 건너뛴다. 저장하지 않는다.
- 같은 그룹 안에서 드래그하면 쌓임 순서(`order`)를 바꾼다. `traits.z()`가 있는 레이어만 가능하다.
- 🔍로 이름·id·파라미터 라벨을 검색한다.

### 6-3. 인스펙터

- 파라미터 키의 첫 마디로 섹션을 나눈다. 섹션 제목 옆에 이 범위에서 덮어쓴 값이 있는지 배지로 알린다.
- 수치는 **슬라이더가 기본이고 숫자 입력은 보조**다(`docs/03` §3-3-4 제2 규칙: "보면서 맞춘다"). Shift+드래그는 미세 조정이다. 범위 밖 입력은 경계값으로 고치고 잠깐 빨간 테두리를 보인다.
- **출처 배지**: `기본` / `수정됨` / `장면` / `모바일` / `장면·모바일`. 배지를 누르면 그 값이 어디서 왔는지 해석 순서(§4-5)를 펼쳐 보여 준다. 각 파라미터에 ↺(이 범위의 값 지우기)를 둔다.
- 파라미터에 마우스를 올리면 무대에서 해당 레이어 윤곽을 강조한다.
- 텍스트는 `i18n`이면 `ko`/`en` 탭을 둔다. 한쪽만 채우면 내보낼 때 경고한다.
- 이미지는 드롭존이다. 초안에서는 data URL로 저장하고(최대 2MB), `apply`가 파일로 뽑아낸다(§7-2).
- 이미지·영상 파라미터 옆에 **`프롬프트` 버튼**을 둔다. 현재 값의 파일 경로로 [`prompts/catalog.json`](../prompts/catalog.json)을 찾아 그 에셋의 썸네일, 도구, 프롬프트 원문(복사 버튼 포함)을 작은 팝오버로 보여 준다. 기록이 없으면 `프롬프트 기록 없음 — prompts/<앱>.md에 카드를 추가하세요`를 띄운다. 새 이미지를 넣었는데 카드가 없으면 `apply`(§7-2)가 경고한다. `catalog.json`은 생성물이므로 패널은 읽기만 한다.

### 6-4. 범위 · 선택 · 기록

| 조작 | 동작 |
|---|---|
| 장면 선택 `[digital ▾]` | 편집 범위를 그 장면으로 바꾸고, 무대도 그 장면으로 전환한다. `모든 장면`이면 base에 쓴다 |
| 화면 선택 | 편집 범위를 그 화면으로 바꾼다. 무대 크기는 바꾸지 않는다. 현재 창과 범위가 다르면 경고 띠 `모바일 값을 편집 중 — 지금 창은 데스크톱이라 보이지 않아요 [창 크기 맞추기]`를 띄운다. `현재 화면 따라가기`를 켜면 창 크기에 맞춰 자동으로 바뀐다 |
| `V` 또는 ⌖ | 선택 모드. 무대 위에서 가리키면 레이어 윤곽과 이름이 뜨고, 클릭하면 선택한다. 같은 자리를 다시 클릭하면 아래 레이어로 순환한다 |
| `Ctrl+Z` / `Ctrl+Shift+Z` | 되돌리기 / 다시 하기(100단계). 슬라이더 드래그 한 번은 한 단계로 친다 |
| `Esc` | 선택 해제 → 선택 모드 종료 → 패널 접기 순서 |
| `[`, `]` | 이전/다음 레이어 |

**선택 판정 주의.** potato의 무대처럼 `pointer-events: none`인 레이어는 `elementsFromPoint`에 잡히지 않는다. 그래서 선택은 모든 `[data-layer]`·`el` 요소의 사각형을 직접 구해 판정한다. 겹치면 쌓임 순서(z-index, DOM 순서)가 위인 것부터 고른다. 선택 모드에서는 투명 오버레이가 클릭을 가로채므로 작품 버튼이 눌리지 않는다.

### 6-5. 변경 목록 · 파일 · 상태

- **변경 목록**: 게시본과 초안의 차이를 레이어 › 범위 › 파라미터(이전 → 이후) 순서로 보여 준다. 항목별로 되돌릴 수 있다. 내보내기 전에 확인하는 곳이다.
- **내보내기**: `layers.values.json`(차이만 담음)을 내려받는다. 파일 이름에 작품 id와 시각을 붙인다.
- **가져오기**: 파일 크기 256KB 이하, 형식 `iw-layers/1`, 작품 id가 일치해야 한다. 그다음 차이 미리보기(`변경 12 · 알 수 없는 값 1 · 범위 밖 2(경계값으로 고침)`)를 보여 주고, [초안에 적용]을 누르면 적용한다.
- **게시본으로 보기**: 초안을 잠시 끄고 게시본을 본다.
- **초안 지우기**: 확인을 받고 지운다. 토스트에서 되돌리기를 제공한다.
- **상태**: `초안 · 저장됨 hh:mm`(400ms 디바운스로 localStorage에 저장) / `저장 안 됨 — 이 브라우저는 저장소를 막고 있어요. 내보내기로 보관하세요` / `게시본과 같음`.

### 6-6. 접근성

패널 컨트롤은 전부 레이블이 있는 네이티브 입력(`input type=range` 등)이다. 탭 순서는 목록 → 인스펙터 → 하단 버튼이다. 패널을 연 버튼으로 포커스를 돌려준다. 선택 모드는 키보드로도 쓸 수 있다(`[`, `]`, Enter).

## 7. 저장 · 게시 · 관람자 설정

### 7-1. 네 층의 원천

| 층 | 원천 | 누가 바꾸나 | 저장 |
|---|---|---|---|
| 구조 (레이어·파라미터·범위·바인딩·장면 목록) | `layers.manifest.js` | 개발자 | git |
| 게시값 | `layers.values.json` (+ 정적 앱은 생성 `layers.values.js`·`layers.css`) | 편집자 → `apply` → 커밋 | git (허브 작품은 2단계에서 R2 가능, §7-3) |
| 초안 | `localStorage iw-layers:<work>:draft` | 편집자 | 편집한 브라우저 |
| 관람자 설정 | `localStorage iw-layers:<work>:viewer` — `viewer: true` 파라미터만 | 관람자 | 관람자 브라우저 |

localStorage는 읽기와 쓰기를 모두 try/catch로 감싼다. 실패하면 이번 세션 메모리에서만 동작하고 상태에 그 사실을 알린다(docs/10 교훈). 값을 읽을 때마다 `cleanValues`로 검증한다.

### 7-2. 게시 흐름 (1단계, 모든 앱 공통)

```
패널 [내보내기] → potato-designer-layers-2026-09-23T1042.json
  → pnpm layers:apply potato-designer <파일>
      ① 형식·작품·버전 검증, 필요하면 migrate
      ② 범위 밖 값을 경계로 고치고 보고 (--strict면 실패)
      ③ data URL 이미지 → <앱>/assets/layers/<sha256 앞 12자>.<ext> 로 추출, 경로 교체
      ④ layers.values.json 저장 (키 정렬 — diff가 깨끗하게)
      ⑤ layer-kit build: layers.css · layers.values.js · (정적 앱) HTML 굽기
      ⑥ layer-lint 실행
  → git diff 확인 → 커밋 → 각 앱의 기존 배포 절차
```

배포는 이 흐름에 넣지 않는다. 배포는 앱마다 기존 절차대로 하고, 사용자가 실행한다.

### 7-3. 허브 경로 (2단계, L8b)

허브(jooho-lab)는 이미 소유자 전용 `PUT /api/content`(ETag 충돌 검사, 서버 재검증)를 갖고 있다. 그 옆에 `GET/PUT /api/layers/<work>`를 추가해서, 허브에 임베드된 작품의 게시값을 R2 `layers/<work>.json`에 둔다. 서버는 같은 `cleanValues`로 재검증한다(서버용 매니페스트 스냅샷이 필요하다). 작품이 허브 아래(`/experiences/<id>/`)에서 돌 때만 이 어댑터를 쓰고, 단독 실행에서는 파일 경로를 쓴다. 보안 리뷰와 사용자 승인 뒤에 한다.

### 7-4. 편집 모드 진입

- `?edit=1` 쿼리를 쓴다. 기본값으로는 `localhost`·`127.0.0.1`·`file:`에서만 열린다. 배포본에서 열려면 매니페스트에 `editor: { public: true }`를 둔다. 공개로 열어도 초안은 그 사람 브라우저에만 저장되므로 다른 관람자에게는 영향이 없다. 그래도 기본을 닫힘으로 두는 이유는 관람자가 우연히 편집기를 보지 않게 하려는 것이다.
- 허브 임베드: 허브 소유자 인증이 통과하면 허브 셸이 iframe URL에 `edit=1`을 붙인다. 허브 게시(§7-3)는 서버가 다시 인증한다.
- 기존 앱의 편집 입구(dawn-store 설정 패널 `작품 편집`, 허브 편집기)는 이 패널로 합친다. dawn-store 이야기 편집 입구는 `docs/09`와 공유한다(§9-3).

### 7-5. 관람자 설정

`viewer: true` 파라미터만 관람자가 바꿀 수 있다. 앱의 기존 설정 UI가 `host.viewerParams()`를 받아 컨트롤을 그린다. 전체 레이어 패널을 관람자에게 열지 않는다. 대상 예: day-walk 캐릭터·새 보이기, dawn-store 자막 크기, potato 모션 강도. 기존 관람자 설정 키(`dawn-store-preferences-v1`, `day-walk:v1`의 settings, `juho-village-preferences-v1`)는 이름을 바꾸지 않는다. 대응하는 필드만 이관하고, 이관 여부를 기록해 두 번 옮기지 않는다(`docs/03` §0-5 키 규칙).

## 8. 품질 게이트 — "빠짐없이 바꿀 수 있다"를 기계로 확인

### 8-1. `layer-lint` (정적, 각 앱 `check`에 포함)

| # | 규칙 | 실패 예 |
|---|---|---|
| 1 | 매니페스트가 유효하다: id·키 형식, 중복, 기본값이 범위 안, 바인딩 형식, CSS 변수 이름 충돌 | `pointer.x`와 `pointer-x`가 같은 변수가 됨 |
| 2 | **레이어 대응**: 매니페스트의 `el`이 HTML/JSX에서 요소를 찾는다. 반대로 `data-layer` 속성은 모두 매니페스트에 있다 | `.ticker`를 삭제했는데 레이어가 남음 |
| 3 | **바인딩 대응**: 모든 CSS 바인딩 변수가 CSS 어딘가에서 `var()`로 쓰인다. CSS의 모든 `--L-*` 참조는 선언돼 있다 | 오타 `--L-charcter-x` |
| 4 | **하드코딩 금지**: 레이어 요소를 겨냥한 CSS 규칙에서 조정 가능 속성(위치·크기·색·불투명도·transform·filter·글자 크기·애니메이션 시간·z-index)은 `var()`를 써야 한다. 구조상 필요한 리터럴에는 선언 옆에 `/* layer-fixed: 이유 */`를 단다 | `.stage-word{top:7%}` |
| 5 | JS의 레이어 코드(입력·장면 처리) 안에 수치 리터럴 강도가 없다. 대상은 `host.input` 호출 주변과 `style.setProperty` 호출이다 | `pointer.x * 22` |
| 6 | 생성물 최신성: `layers.css`, `layers.values.js`, 구운 HTML, 벤더 복사본의 해시가 원천과 맞는다 | 매니페스트를 고치고 build를 안 돌림 |
| 7 | 값 파일: 형식 유효. 고아 값은 경고. data URL은 오류(`apply`를 거치지 않았다는 뜻) | |
| 8 | `var(--x, 리터럴)` 폴백 금지 (§4-6) | |

규칙 4는 postcss(개발 의존성, 런타임에는 들어가지 않음)로 CSS를 파싱해서 검사한다. 선택자가 레이어 요소를 겨냥하는지는 두 방법으로 판정한다. 매니페스트 `el` 선택자 목록과 대조하고, 규칙 2의 HTML 스캔 결과로 클래스·속성을 대조한다. React 앱에서 JSX 인라인 `style`에 수치 리터럴을 쓰면 규칙 5가 경고한다. 스타일은 CSS 파일로 옮기는 것이 원칙이다.

### 8-2. `layer-probe` (브라우저, Playwright)

"컨트롤이 있다"만으로는 부족하고 "컨트롤이 **실제로 화면을 바꾼다**"까지 확인해야 한다. `docs/03` §3-2의 Design Check를 자동화한 것이다.

```
for 화면 B in [기본, …breakpoints]:           // 뷰포트를 그 화면 폭으로 맞춤
  for 장면 S in scenes:
    입력을 (0.5, 0.5)로 고정, 동작 줄이기 끔
    for 파라미터 P (이 화면·장면에서 의미 있는 것만):
      관측 = 레이어 요소와 자식의 계산 스타일, 텍스트, 속성, fn 호출 기록
      host.set(P, 탐침값)                      // 수: 범위 안 다른 값, 색: 보색, 토글: 반대, 목록: 다음, 텍스트: +"·probe"
      2프레임 대기 → 다시 관측
      변화 없음 → 실패 "character.pointer.y: 값을 바꿔도 화면이 그대로"
      되돌림
```

- 반응형이 아닌 파라미터는 기본 화면에서 한 번만 검사한다. 장면에서 못 바꾸는 파라미터는 장면을 돌며 검사하지 않는다.
- 캔버스 레이어는 앱이 테스트 모드에서 `window.__layerProbe.snapshot(layerId)`를 제공해야 한다. 렌더 상태를 직렬화한 값이다.
- 결과는 `projects/<app>/.layer-probe.json`에 파라미터별 통과/실패로 남기고, 실패가 하나라도 있으면 `check`가 실패한다.
- 시간 예산: 앱당 60초 이내. 넘으면 탐침을 레이어 단위로 병렬 실행한다.

### 8-3. 규칙으로도 강제

- `AGENTS.md`(Claude는 `CLAUDE.md`의 `@AGENTS.md`로 읽음)에 **레이어 계약**을 필수 규칙으로 둔다. 새 인터랙티브이거나 시각 요소를 추가하는 작업이면 매니페스트를 갱신하고 lint·probe를 통과해야 완료다.
- 인터랙티브 작업 플랜에는 **"레이어 계약" 항목**을 적는다: 추가·변경한 레이어와 파라미터, 고정값과 그 이유, lint·probe 결과. 이 항목이 없으면 플랜 게이트 G1(완전성)을 REASSIGN으로 처리한다.
- 새 작품은 `layer-kit init <work>`로 시작한다. 매니페스트 뼈대(`global` 레이어, 기본 화면 2개), 빈 값 파일, check 스크립트 연결이 생성된다.

## 11. 보안 · 견고성

- 텍스트는 `textContent`로만 넣는다. HTML 파라미터 타입은 없다.
- 이미지는 허용 목록만 받는다: 앱 내부 상대 경로(`./assets/…`, `/assets/…`), 초안 한정 `data:image/(png|jpeg|webp|gif);base64`(2MB 이하), 허브 `/api/media/<uuid>.<ext>`. SVG data URL과 `javascript:`는 거부한다. CSS `url()`에 넣을 때는 따옴표로 감싸고 이스케이프한다.
- CSS로 나가는 값은 **숫자 + 정의된 단위**, 검증된 hex, enum 목록 값, 검증된 `cubic-bezier`뿐이다. 자유 CSS 문자열을 받는 파라미터는 없다. 그래서 값 파일로 CSS를 주입할 수 없다.
- 가져오기는 256KB 이하이고 `JSON.parse` 뒤 `cleanValues`를 거친다. 프로토타입 오염 키(`__proto__`, `constructor`, `prototype`)는 버린다.
- 편집 모드는 기본적으로 로컬에서만 열린다(§7-4). 게시는 git 커밋이거나 허브 서버 재인증을 거친다. 클라이언트 편집기가 게시 권한을 갖지 않는다.
- 저장소가 막히면 메모리에서만 동작하고, 그 상태를 알리며 내보내기를 권한다.

## 13. 기본값으로 정한 것 (사용자 확인이 필요하면 바꿀 수 있음)

| 질문 | 이 설계의 기본값 | 바꾸면 |
|---|---|---|
| 관람자도 레이어를 바꾸나? | 아니다. 제작자(편집 모드)가 전부 바꾸고, 관람자는 앱이 `viewer: true`로 고른 몇 개만 바꾼다 | 관람자 패널을 따로 만들고 노출 목록을 정한다 |

| 시간축 키프레임 편집이 필요한가? | 1단계에서는 장면 전환과 입력 반응으로 해결 | 레이어 킷에 `timeline` 모델과 타임라인 UI를 추가하는 별도 설계 |
