# 14. 기본 비주얼 방식 — 3D 느낌 이미지 + CSS 깊이 (2.5D)

작성: 2026-10-04 · 상태: **채택 · POTATO에서 검증됨**.
사용자 결정(2026-10-04): "인터랙티브 웹은 이런 느낌의 그림 제작을 주로 쓸 거니까 잘 적어 둬." — POTATO 캐릭터 방식을 인터랙티브 웹의 **기본 비주얼 제작 방식**으로 삼는다.

한 줄 요약: **3D 피규어처럼 렌더된 투명 PNG 한 장**을 만들고, 웹에서는 **CSS 원근으로 마우스에 맞춰 조금만** 기울이고 띄운다. 입체감의 대부분은 그림 속의 과감한 원근과 스튜디오 조명에서 나오고, 웹은 "살아 있다"는 느낌만 더한다. 3D 모델·Three.js·Blender가 필요 없다.

참고한 자료: [POTATO README](../projects/potato-designer/README.md)·[QA](../projects/potato-designer/QA.md)·`dist/app.js`·`style.css`·`layers.manifest.js`, [프롬프트 카드](../prompts/potato-designer.md), [templates §2·§6](../prompts/templates.md), [10번](10-인터랙티브-개발-참고원칙.md)의 POTATO 교훈, [11번](11-레이어-설정-시스템-설계.md) 레이어 계약, [13번](13-3D-공통-제작-파이프라인-설계.md) 실제 3D 파이프라인.

## 1. 언제 이 방식을 쓰고, 언제 실제 3D(13번)로 가나

기본은 이 방식이다. 아래 표에서 "13번"에 해당하는 요구가 있을 때만 [Meshy → Blender → Three.js](13-3D-공통-제작-파이프라인-설계.md)를 쓴다.

| 화면에 필요한 것 | 이 방식 | 대안 |
|---|---|---|
| 캐릭터·물건이 마우스에 반응해 살짝 기울고 떠다님 | **충분** (POTATO) | — |
| 장면마다 분위기(배경색·강조색·기울기·크기)가 바뀜 | **충분** (POTATO 3장면) | — |
| 장면마다 다른 자세 | 자세별로 이미지를 따로 생성 | 같은 인물 유지는 미검증(§6) |
| 날갯짓·걷기 같은 짧은 반복 동작 | 스프라이트 2~N프레임 ([templates §6](../prompts/templates.md#6-스프라이트-시트-투명-배경), 하루 산책 새에서 검증) | 자유로운 관절 동작은 13번 |
| 뒷면·옆면을 보여 주거나 크게 돌림(±15° 이상) | **불가** — 평면이 드러난다 | 13번 |
| 카메라가 공간 안을 걸어 다님 | 불가 | 13번, 또는 JOOHO LAB식 파노라마 평면 |
| 같은 캐릭터를 숏폼 영상에서 여러 각도로 재사용 | 불가 | 13번 |

이 경계는 방식의 기술적 한계에서 정리한 것이다. 사용자가 "주로"라고 했으므로 13번 설계는 폐기하지 않고 예외 경로로 남긴다. 13번이 제안한 POTATO 실제 3D 첫 검증을 계속할지는 사용자 결정이 아직 없다.

## 2. 그림 만들기

### 2-1. 프롬프트 틀

검증된 원문은 [prompts/potato-designer.md](../prompts/potato-designer.md)에 있고, 복사해서 쓰는 틀은 [templates §2](../prompts/templates.md#2-캐릭터-단독-투명-배경)에 있다.

```text
Premium stylized 3D collectible [인물·물건 설명], [머리], [얼굴 소품], [상의], [하의], [신발].
[자세 — 카메라 쪽으로 과감한 원근: Extremely foreshortened … toward camera with huge … in lower-right foreground], [손 위치].
Full figure within square frame, genuine transparent background, soft neutral studio lighting, detailed cloth, no text, no UI, no floor.
```

### 2-2. 문구마다 맡은 역할

| 문구 | 왜 넣나 |
|---|---|
| `Premium stylized 3D collectible` | 피규어 렌더 질감과 음영. 평면 그림이 "덩어리"로 보이게 하는 핵심 |
| `Extremely foreshortened … toward camera, huge … in foreground` | **깊이를 그림 안에 넣는다.** 웹에서는 ±10° 안팎만 돌리므로 깊이의 대부분은 이 원근이 만든다. 가장 가까운 부위(POTATO는 운동화 밑창)가 화면을 크게 차지해야 한다 |
| `soft neutral studio lighting` | 색이 들어간 조명이 없어야 장면별 배경색·강조색을 바꿔도 어울린다. POTATO는 배경색 3개 위에서 같은 그림을 쓴다 |
| `genuine transparent background, no floor` | 그림자를 CSS 레이어로 따로 그리기 위해서. 바닥이 그림에 있으면 캐릭터가 떠오를 때 바닥도 같이 뜬다 |
| `Full figure within square frame` | 회전·확대해도 잘리지 않게. 실제 결과는 가장자리 16px 안쪽까지 꽉 차므로(1254px 중 46~1236 × 16~1237) **여백은 CSS 컨테이너에서** 확보한다 |
| `no text, no UI` | 그림 속 글자는 고칠 수 없다. 문구는 레이어 텍스트로([templates §10](../prompts/templates.md#10-공통-규칙)) |

### 2-3. 생성 설정과 합격 기준

- 도구: 내장 `image_gen`(gpt-image). 2026-09-22 POTATO에서 진짜 알파 채널로 나왔다. 도구 이름은 시점 의존 정보이므로 쓸 때 다시 확인한다.
- 크기: 정사각형. POTATO는 1254×1254 PNG 1.6MB를 그대로 썼다(WebP 변환은 미검증, §6).
- 후보: 한 번에 여러 장 뽑아 고른다. 고른 이유와 버린 후보의 이유를 카드에 남긴다.

합격 기준 — 하나라도 실패하면 다시 만든다.

1. **알파가 진짜인가.** 같은 요청으로 하루 산책 새는 체커보드 무늬를 그려 버렸다. 이 PC에서 확인한 명령:
   ```bash
   py -3 -c "from PIL import Image; a=Image.open('character.png').getchannel('A'); w,h=a.size; print([a.getpixel(p) for p in [(0,0),(w-1,0),(0,h-1),(w-1,h-1)]], round(a.histogram()[0]/(w*h),2))"
   ```
   네 모서리가 0이고 완전 투명 비율이 0보다 커야 한다(POTATO: `[0, 0, 1, 0] 0.51`). 가짜면 [templates §6](../prompts/templates.md#6-스프라이트-시트-투명-배경)의 초록 배경(#00FF00) 방식으로 다시 받는다.
2. 진한 배경 위에 올렸을 때 **흰 테두리(헤일로)가 없는가.**
3. 그 앱의 **장면별 배경색 위에서 모두** 어울리는가 — 관리자에서 장면을 바꿔 확인.
4. 원근이 충분히 과감한가 — 가장 가까운 부위가 그림의 큰 비율을 차지하는가.
5. 기록: [prompts/](../prompts/README.md)에 카드(프롬프트 원문 그대로)를 쓰고 `pnpm prompts:build`.

## 3. 웹에서 입체감 주기

### 3-1. 구조 — 움직임 하나에 요소 하나

```html
<div class="stage" aria-hidden="true">          <!-- perspective 기준 -->
  <div class="ground-shadow"></div>               <!-- 바닥 그림자 (형제, 캐릭터와 따로 움직임) -->
  <div class="character-motion">                  <!-- ① 등장 모션 (한 번) -->
    <div class="character-parallax">              <!-- ② 마우스 반응 + 장면 기울기·배율 -->
      <img class="character" data-layer-image="character/src" src="./assets/character.png"
           alt="" width="1254" height="1254" draggable="false">  <!-- ③ 떠다님 (반복) -->
    </div>
  </div>
</div>
```

요소를 셋으로 나누는 이유: 한 요소에는 `transform`이 하나뿐이라, 등장 키프레임·마우스 변환·떠다님 키프레임을 한 요소에 걸면 서로 덮어쓴다. 움직임마다 요소를 하나씩 맡기면 셋이 곱해져 합성되고, 레이어 파라미터도 따로 조절할 수 있다.

### 3-2. 마우스 → CSS 변수

JS는 위치만 -1~1로 정규화해 넘기고, 각도·이동량 계산은 CSS가 한다(`app.js:36-48`).

```js
hero.addEventListener('pointermove', (event) => {
  if (event.pointerType === 'touch' || paused) return;          // 터치는 반응하지 않음
  const box = hero.getBoundingClientRect();
  pointer = { x: (event.clientX - box.left) / box.width * 2 - 1,
              y: (event.clientY - box.top) / box.height * 2 - 1 };
  if (!frame) frame = requestAnimationFrame(renderPointer);     // 프레임당 한 번만 반영
});
hero.addEventListener('pointerleave', () => { pointer = { x: 0, y: 0 }; /* rAF로 반영 */ });
// renderPointer: 정지·탭 숨김·모달 열림이면 건너뛰고, 아니면 --in-pointer-x/y를 루트에 설정
```

```css
:root{
  --px: calc(var(--in-pointer-x) * var(--L-character-pointer-x));            /* 좌우 이동 */
  --py: calc(var(--in-pointer-y) * var(--L-character-pointer-y));            /* 상하 이동 */
  --rx: calc(var(--in-pointer-y) * var(--L-character-pointer-tilt-x) * -1);  /* 위를 가리키면 뒤로 젖힘 */
  --ry: calc(var(--in-pointer-x) * var(--L-character-pointer-tilt-y));
}
.character-parallax{
  transform: translate3d(var(--px),var(--py),0) rotateX(var(--rx)) rotateY(var(--ry))
             rotate(var(--rz)) scale(var(--zoom));                           /* --rz·--zoom = 장면 값 */
  transform-style: preserve-3d; will-change: transform;
}
@media (prefers-reduced-motion: reduce){
  .character-parallax{ transform: rotate(var(--rz)) scale(var(--zoom)) !important }  /* 자세만 남김 */
}
```

### 3-3. 시작값 (POTATO에서 검증)

새 앱은 이 값에서 시작해 관리자에서 조정한다. 모두 레이어 파라미터이며 CSS에 리터럴로 쓰지 않는다.

| 레이어 · 파라미터 | 값 | 메모 |
|---|---|---|
| `stage` perspective | 1200px | 작을수록 기울기가 과장된다 |
| `character` pointer.x / pointer.y | 22px / 13px | 좌우 이동이 상하보다 크다 |
| `character` pointer.tilt-x / tilt-y | 6° / 9° | **10° 안팎을 넘기지 않는다** — 넘기면 종이처럼 납작한 게 드러난다 |
| `character` transition (parallax) | `transform .12s linear` | rAF 갱신 사이를 메운다 |
| `character` tilt / zoom (장면별) | Brand -5°·1 / Digital 3°·0.94 / Character -10°·1.05 | 분야 전환 = 2D 회전 + 배율만 |
| `character` transform-origin | 60% 60% | 원근상 무게중심 쪽으로 |
| `character` 등장 arrival | 1700ms `cubic-bezier(.17,.7,.27,1)` · 0% `translate(15%,-16%) scale(.48) rotate(15deg)` 투명 → 15% 불투명 → 70% `scale(1.04) rotate(-1deg)` → 100% 제자리 | 멀리서 날아와 살짝 넘쳤다가 선다 |
| `character` 떠다님 float | 7000ms ease-in-out · 50%에서 `translateY(-18px) rotate(2deg)` | 무한 반복 |
| `character` filter | `drop-shadow(8px 15px 12px #26312912)` | 그림 가장자리에만 붙는 옅은 그림자 |
| `shadow` 바닥 그림자 | 타원, `blur(19px)`, `#303b2c23`, `rotate(-8deg)` | 그림 원근 방향에 맞춰 기울인다 |
| `shadow` 숨쉬기 | **떠다님과 같은 7000ms** · 50%에서 `scale(.88)`, 불투명도 .85 → .5 | 캐릭터가 올라갈 때 그림자가 작고 옅어져서 높이로 읽힌다 |

### 3-4. 지킬 것

| 규칙 | 이유·출처 |
|---|---|
| 그림자 주기 = 떠다님 주기 | 엇갈리면 높이가 아니라 따로 노는 두 물체로 보인다 |
| 터치에는 포인터 반응을 걸지 않는다. 모바일은 등장·떠다님만 | 스크롤과 충돌. 기울기 센서는 미검증(§6) |
| `pointerleave`에서 0으로 복귀, 갱신은 rAF로 1회 | 가장자리에서 멈춘 자세가 남지 않게, 이벤트 폭주 방지 |
| 사용자 정지·OS 동작 줄이기·배경 정지(탭 숨김·모달)를 구분하고 장면 값은 보존 | [10번](10-인터랙티브-개발-참고원칙.md) POTATO 교훈 |
| 무대가 그리드 자식이면 최소 크기 0, 무대 영역 `overflow: clip` | 캐릭터가 헤더·푸터를 침범한 결함(10번) |
| 무대 전체 `aria-hidden="true"`, 이미지 `alt=""`, `draggable="false"` | 장식 요소. 정보는 본문 텍스트로 |
| 그림 교체는 `character.src` 파라미터로 | 관리자에서 이미지만 바꿔 다른 캐릭터로 재사용 |

### 3-5. 레이어 계약

[11번](11-레이어-설정-시스템-설계.md) 계약을 그대로 따른다. POTATO 매니페스트의 `stage`·`character`·`shadow` 레이어가 틀이다.

- `stage`: perspective, 위치·크기
- `character`: `src`, `tilt`(→`--rz`), `zoom`(→`--zoom`), `pointer.x`·`pointer.y`·`pointer.tilt-x`·`pointer.tilt-y`, `motion.arrival.*`·`motion.float.*`(시간·지연·속도 변화), 등장·떠다님 키프레임 값, filter, transform-origin
- `shadow`: 위치·크기·색·blur, `motion.shadow-breathe.*`, 숨쉬기 키프레임 값
- 장면별(`scenes.*.set.character.tilt/zoom`)·화면 크기별 override
- 완료 조건: 앱 `check`에서 layer-kit lint 오류 0, probe 전 파라미터 통과

## 6. 확인 상태

**검증됨 (POTATO, 2026-09-22~23)**: 캐릭터 1장 생성과 진짜 알파 확인(2026-10-04 재측정), 마우스 깊이·등장·떠다님·그림자, 장면 3개 전환, 동작 줄이기, 브라우저 검사 140개, 레이어 probe 619/619, lint 오류 0([QA](../projects/potato-designer/QA.md)).

**아직 확인하지 않음** — 처음 쓰는 앱이 검증하고 이 절을 갱신한다.

- 캐릭터가 아닌 소품·물건을 같은 문구로 만들 때의 품질
- 같은 인물의 다른 자세를 참조 이미지로 일관되게 뽑을 수 있는지
- WebP/AVIF 변환 후 알파 가장자리 품질과 용량
- 모바일 기울기 센서(`deviceorientation`) 반응과 권한 흐름
- 한 무대에 캐릭터 여러 개를 두었을 때 겹침 순서와 시차(깊이별 반응 강도 차등)
