## 4. 전사 요약 — 영상에서만 나오는 이야기

녹취(Q&A)와 겹치지 않는 내용만 뽑았다. 시각은 각 편 기준.

### 4-1. 포탈 스페이스는 어떻게 시작됐나 (3편)
- **출발점은 소셜에서 본 오프-액시스 영상**. "바이브 코딩 예제들은 밋밋하고 기하학 도형만 있다. 여기다 내가 디자인을 덧대면 어떨까." (0:38~0:45)
- **첫 프롬프트는 그리드 하나**: "그리드로 카메라를 연동해서 움직이나 안 움직이나, 여기까지만 딱 하고." 되면 그리드 간격·라이트 옵션을 추가하고, **그 다음 레퍼런스를 모으러 간다.** (0:50~1:13) → 기술 검증 → 레퍼런스 → 디자인 순서.
- 히어로 캐릭터 생성기: Nano Banana로 넣었더니 "70년대 미국 애니메이션"처럼 나와 실망 → 그날 나온 GPT Image 2로 다시 하니 바로 마음에 듦 (1:41~2:01). 오늘(강연일) GPT 2.5 발표: 수정 시 위치 흔들림·재사용 노이즈가 고쳐졌다 (2:05~2:26).
- **순서: 캐릭터 먼저 → 어울리는 배경 요청 → 캐릭터 빼달라 → 바닥/왼쪽/뒷면으로 분할** (2:36~3:30). 크리처는 "랜덤하게 만들어도 컨셉 아트급이 계속 나온다" (2:45~3:03).
- 3D 변환: Tripo나 Meshy. TV 같은 중간 레이어도 로우폴리 **스마트 메시**로 (3:50~4:10).
- 바이브 코딩 재개: GLB 불러오기 → 크기 조절 → "라이트 기능 추가해줘" → 방향·추가 라이트·색상 (4:14~4:33). "뚝딱은 아니다. 고생해서 나온다."
- **왜 매트릭스인가**: "멋있긴 한데 사람들한테 공감이 될까? 한 번 보고 말지 않을까." → 좋아하는 영화 명장면을 공간형으로. 훈련장·빨간약 파란약·총알 피하기 등 **4개 씬을 하루 만에** (4:52~5:33).
- 손바닥 제어: 인터넷에서 마이너리티 리포트식 손바닥 카메라 제어를 보고 **바로 그날 기능으로 넣음** (5:38~5:54). 배포판의 "Hand orbit" 버튼.
- 가우시안 스플래팅: 3D 파일보다 가볍고 고화질. AI 이미지 → 영상 → 스플랫. 다음 갤러리는 이걸로, **돌아다니기** 기능 추가 예정 (5:56~6:38).
- 게임 아이디어: "레이싱·슈팅 게임 할 때 몸을 기울이잖아요. 총구를 내 얼굴로 겨냥하면 어떨까." → Mini Kingdom (6:41~7:05).

### 4-2. Mini Kingdom 게임 (2편 0:00~5:03)
- 스토리 모드는 구글 로그인, 카메라 필수. **얼굴로 총구 방향**, 스페이스바 세게 누르면 강한 탄, 샷건(당겨서 다발), 폭탄(주변 전멸).
- **스테이지 관리자**: 스테이지별 적 수(1스테이지 4명, 2스테이지 5명…), 배경, 체력 표시, 무기·폭발 이펙트를 관리자에서 조절. "바이브 코딩으로 매번 수정 요청하는 게 아니라 라이브 프리뷰로 직접 수정" (0:52~1:36).
- 캐릭터 파이프라인: 레퍼런스 → 캐릭터 생성 → 마음에 드는 하나로 **베리에이션**(더 센 몬스터) → 어울리는 배경 → "이 배경과 캐릭터로 게임 인트로 만들어줘" → 제목까지 이미지 안에 넣어줌("로켓 아레나 미니캠") → **버튼만 떼서 메뉴로, 배경은 영상으로** (1:41~2:37).
- **스테이지 전환 영상**: 왼쪽 이미지(현재 스테이지)·오른쪽 이미지(다음 스테이지)를 Start/End로 "1스테이지에서 2스테이지로 걸어가" 영상 생성 → 스테이지 넘어갈 때 재생 (2:41~3:01).
- **UI 킷 프롬프트**: "하나씩 만들지 말고 UI 킷으로. 윗줄 기본, 둘째 줄 하이라이트, 아랫줄 비활성." 폰트도 킷으로 (3:05~3:29).
- 튜토리얼 영상(몸을 좌우로 움직이면 방향), 홍보용 후킹 영상도 제작 (3:36~4:22).
- **레슨**: "완벽한 기획 후 완성보다 **일단 실행**. 빠른 이터레이션으로 만들면서 변형하는 아이디어가 요즘 세상에 맞다." 오프-액시스 → 사이파이 → 매트릭스 → 게임으로 변형된 과정 자체가 근거 (4:26~5:03).

### 4-3. AI Movie (2편 5:05~9:47)
- 작년 같은 자리에서 발표한 작품. 3편의 영화로 AI의 발전·위험성·리더를 다룸.

## 5. 모노레포에 추가로 반영할 원칙 (영상에서 도출)

1. **기술 검증 → 레퍼런스 → 디자인 순서.** 첫 프롬프트는 그리드 하나. 되는지 확인하고 나서 에셋을 만든다.
2. **어드민은 클라이언트와의 소통 레이어다.** 납품용 앱은 반드시 관리자 노출 모드 `auth`로, 문구·글씨 크기·날짜·발송이 클라이언트 손에 있어야 한다.
3. **슬라이더 컨트롤러로 디자인을 재현한다.** 캡처를 프롬프트에 넣는 게 아니라, 컨트롤을 만들고 직접 맞춘다. → `core-admin` 스키마→폼 렌더러가 핵심.
4. **자막·오버레이는 영상에 굽지 않는다.** 웹 인코딩에서 뭉개진다.
5. **앱 안에서 에셋 업로드까지 되면 바이브 코딩이 필요 없어진다.** 그 시점이 "툴 완성".
6. **외부 연동 슬롯**: Notion(구독자·데이터 뷰), Google Calendar(일정·알람), 이메일 발송, YouTube RSS(썸네일 자동화), 지갑 연결.
7. **작품 간 연속성**: 이스터에그 비밀번호 체인 → `app-info`에 `secretCode`, `nextWorkHint` 필드.
8. **일단 실행.** 완벽한 기획보다 만들면서 변형. 플랜은 노드 3~4개까지만.
