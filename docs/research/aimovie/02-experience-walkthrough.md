# AI MOVIE (gryun-aimovie.com) 경험 워크스루

대상: https://gryun-aimovie.com/ (김그륜 작가, 분기형 AI 영화)
방법: `/api/video-flow`, `/api/app-settings` 실데이터 확보 후 Playwright(1440×900 데스크톱 / 390×844 모바일)로 언어선택→인트로→전 분기(좌/상/우)→메인 엔딩→히든 엔딩까지 실제 재생·클릭으로 답사. 로그인은 시도하지 않음(401 확인만).

> **환경 노트**: 이 세션은 Playwright 브라우저를 다른 에이전트(design-your-world 분석)와 **공유**하고 있었다. 탭이 예고 없이 닫히거나 다른 사이트로 바뀌는 충돌이 빈번해, 모든 `evaluate` 호출에 `location.href.includes('gryun-aimovie.com')` 가드를 넣어 오염된 캡처를 걸러냈다. 아래 데이터는 가드를 통과했거나 스크린샷을 직접 육안 확인해 aimovie 콘텐츠로 검증된 것만 수록했다(오염되어 폐기한 스크린샷 4장 제외).

## 1. 플레이 경로 요약

```
[언어선택] --KO--> video1(폭스패러디+감독 인트로)
  --right--> video2(감독 회고) --right--> video3(AI EVOLUTION 포스터)

  video4(A-EYE 포스터) --left--> video4-L(연결샷) --right--> video4-R(연결샷)
    --up--> video4-IN(다큐, 1:57, 타임라인 6포인트, visitedVideo4In=true) --right--> video5
  video5(AI STORY 포스터) --left--> video5-L(연결샷) --right--> video5-R(연결샷)
    --up--> video5-IN(엔딩 다큐, 1:56, 타임라인 4포인트) [메인 엔딩, isEnding]

```

15개 노드 전수(available:true 13개 + available:false 2개) 중 **13개를 실제 재생·전이 확인**, 2개(video3-L/video3-R)는 API에는 정의되어 있으나 **현재 UI에서 진입 경로 자체가 없음**을 확인(§9).

## 3. 공통 UI·오디오·이스터에그

### 3.1 공통 UI
- **네비게이션 화살표**: 원형 버튼(데스크톱 52px), 방향에 따라 `button-left/up/right`(data-testid)로 존재. `arrowInstantVisible:false` — 영상 시작부터 바로 보이지 않고 "끝나기 N초 전"에 나타남(`videoTiming` = 초, 노드별 상이: 8s가 기본, 다큐류는 1s, 짧은 연결샷은 3s).
- **글로우(추천 경로)**: `defaultGlow`(glow1)가 기본으로 빨갛게 펄스. `glowCondition`(glow2)이 설정된 노드는 특정 플래그(`visitedVideo3In`/`visitedVideo4In`)가 서게 되면 **글로우가 glow1→glow2로 이동**한다(둘이 동시에 빛나는 게 아니라 "다음에 안 본 방향"으로 추천이 갈아탐). 실측: video4-L에서 방문 전엔 up이, `video3-IN`을 본 뒤에는 right가 빛남(스크린샷 확인).
- **좌측 화살표가 아예 없는 경우**: video3의 `left`, video4-L의 `left`처럼 목적지(video3-L/video3-R)가 `available:false`면 UI에 버튼 자체가 렌더링되지 않는다. 즉 미완성 분기는 사용자에게 노출되지 않도록 방어돼 있음.
- **스킵 버튼**: 85×42(모바일 85×32) 검정 알약, 화면 하단 중앙. `videoSkip` 플래그로 노드별 on/off(다큐형 -IN 노드와 히든 엔딩은 스킵 불가 — 즉 본편은 스킵 가능해도 "몰입 구간"인 다큐/엔딩은 건너뛰기를 막아둠).
- **타임라인 점프**: -IN 다큐 3종 상단에 진행바+포인트(5/6/4개)가 뜨고, 포인트 클릭 시 **즉시 해당 시각으로 정확히 점프**함을 실측 확인(`timeline-point-3` 클릭 → 2.5s → 105.0s = 01:45로 정확히 이동). 첫 포인트만 `enableHoverPreview:true`(호버 시 미리보기, 나머지는 없음)로 설정돼 있음.
- **언어 토글**: 데스크톱 상단에 `button-lang-toggle`류 UI가 있는 구조(설정 JSON에 `langToggle` 전용 스타일 블록 존재: 활성 텍스트 금색 #f3c614/비활성 흰색, 알약형). 자막 KO/EN 데이터셋은 완전히 분리돼 있고 전 노드에 대응 영문 대사가 준비돼 있음.
- **리플레이**: 최종 엔딩(비디오6-HIDDEN 종료 시)에 "다시보기" 알약 버튼(140×50) 노출, 클릭 시 처음으로.
- **설정/관리자 진입점**: 재생 화면에서는 언어선택 화면을 포함해 별도 톱니바퀴 아이콘이 발견되지 않았다(뮤트 아이콘만 상시 노출). `/admin` 경로는 200으로 응답하나 `/api/auth/user`가 401을 반환 — SPA 셸만 내려오고 실제 진입은 로그인 벽 뒤. **로그인은 시도하지 않음.**
- **푸터 "Created by Gryun Kim"**: 전 노드 하단 중앙 고정, 인스타그램(`instagram.com/kimgryun`) 링크. 언어선택 화면부터 엔딩까지 한 번도 빠짐없이 노출.

### 3.2 오디오
- **BGM**: `/BGM/bgm.mp3` 단일 `<audio data-testid="audio-bgm">` 엘리먼트. `enabledSections`로 섹션별 on/off: intro·video1·**모든 -IN 다큐·히든 엔딩에서는 꺼짐**, video2~5(및 L/R 연결샷)에서만 켜짐. `startAtEndSections`가 video3-IN/video4-IN에 true — 다큐가 끝나는 시점에 정확히 맞춰 BGM이 재개되도록 타이밍이 짜여 있다(임의 재생이 아니라 다음 구간 시작과 동기화). 볼륨 80%, 섹션 전환 시 2초 크로스페이드.
- **더빙 내레이션**: 영상 자체는 **muted=true**로 재생되고, 노드마다 별도 `videoN.mp3`(예: `video1.mp3`, `video4-L.mp3`, `video5-IN.mp3` …)가 **동기화된 두 번째 오디오 트랙**으로 로드된다. 네트워크 로그상 자막이 없는 연결샷(video4-L/R, video5-L/R)에도 mp3가 개별 요청되는 것을 확인 — 자막 유무와 무관하게 오디오 트랙은 전 노드에 준비돼 있음(내레이션 또는 앰비언스로 추정, 내용까지는 검증 못함).
- **언어별 mp3 분기**: 자막 데이터는 KO/EN이 완전히 분리돼 있으나, 이번 캡처(한국어 모드)에서 관측한 오디오 경로는 모두 `videos/videoN.mp3` 형태로 언어 하위폴더가 보이지 않았다(참고로 같은 세션에서 우연히 관측된 DYW 사이트는 `/videos/EN/*.mp3`처럼 언어 폴더가 있었다). **영어 전환 시 mp3가 실제로 교체되는지는 언어 토글을 직접 눌러 확인하지 못했다 — 미검증 항목(§9).**
- **효과음**: `/audio/on.wav`(호버), `/audio/click.wav`(클릭) — 버튼·화살표·스킵·리플레이·언어토글 전부 동일 SFX 세트 사용.

### 3.3 이스터에그 (히든 엔딩)
- 위치: **video5-IN(메인 엔딩) 01:20~01:33 구간**, 화면 하단 우측에 등장하는 **쓰러진 은색 쓰레기통** 위. `data-testid="hidden-link-hidden-1"`인 투명(`fixed cursor-pointer`, 시각적 프리뷰 없음 — `previewEnabled:false`) 히트박스가 그 시점에만 DOM에 나타난다(데스크톱 좌표 기준 x77%/y79%, 약 335×168px).
- 동작: 클릭하면 **비밀번호 입력 없이 곧바로** `video6-HIDDEN`으로 전환된다. 별도 모달/입력폼 testid는 발견되지 않았다 — "비밀번호"는 이번 실측 UI 흐름에는 존재하지 않았다(추측건대 사용자가 전해들은 설명과 실제 배포 버전 사이에 차이가 있거나, 과거 버전에 있었을 가능성. **브루트포스는 시도하지 않았고, 이번 조사에서는 발견되지 않았다는 사실만 보고한다.**).
- 연출: video5-IN의 마지막 프레임(월터 미티 포스터+쓰레기통 거리샷)과 video6-HIDDEN의 시작 프레임이 **완전히 동일한 컷**으로 이어져 끊김이 없다. video6-HIDDEN 자막 "이렇게 모든 영화를 보고 우리는 처음에 만난 공간인…"이 이 연출을 대사로도 확인해준다.

## 5. 모바일(390×844)

- 언어선택 화면은 세로 레이아웃으로 깔끔하게 재배치됨(스크린샷 참조).
- **주의(방법론 캐비닛)**: 뷰포트만 390px로 리사이즈했고 터치 이벤트/모바일 UA 에뮬레이션은 하지 않았다. 그 결과로 보이는 값들:
  - 화살표 버튼이 40px(설정 `design.mobile.circleSize`)이 아니라 **52px(데스크톱 값)** 그대로 렌더링됨.
  - 자막도 설정상 13px(`subtitles.mobile.KO.style.fontSizePx`)인데 실제 화면에서는 큰 글자(체감 28px 이상)로 3줄까지 넘쳐 **화면 하단을 벗어나 잘리는** 것을 확인(스크린샷 `mobile-timeline-jump.png`).
  - 두 값 모두 "모바일 전용 설정이 적용 안 되는" 동일한 패턴이라, 실제 모바일 기기(터치+UA)에서는 다를 가능성이 있다. **재현 시 반드시 진짜 모바일 디바이스/에뮬레이터로 재검증 필요.**
- 인트로 로고 씬은 16:9 소스를 세로로 크롭(object-fit cover)하면서 "GENERATED"/"MOVIE" 같은 가로로 긴 타이포가 좌우로 잘려나간다 — 세로 화면 전용 크롭/리프레임이 준비돼 있지 않음(§7 거친 부분).
- 자막 하단 위치(85%)가 Skip 버튼과 겹치는 문제가 데스크톱보다 모바일에서 더 두드러짐.

## 6. 성능·에러

- **콘솔 에러**: 전체 플레이스루(언어선택→13개 노드→히든엔딩→리플레이) 동안 **딱 1건**, `GET /api/auth/user → 401`(미로그인 상태에서 관리자 세션 확인 시도, 정상적인 기대 동작). 그 외 JS 에러 0건.
- **네트워크**: 첫 페인트에 JS/CSS 번들 1개씩 + `video-flow`/`app-settings` API 2개 + Noto Sans KR 서브셋 woff2 약 15개(글리프 레인지별로 잘게 쪼개져 병렬 다운로드, 개별 파일은 작지만 요청 수가 많음) + `video-INTRO.mp4`(언어선택 화면 배경 루프, video1과 별도 파일) + `video1.mp4`/`video1.mp3` 순으로 로드.
- **프리로드 확인**: 현재 노드를 보는 동안 다음 노드의 mp4+mp3가 이미 매니페스트 요청되는 것을 네트워크 로그로 확인(예: video3-IN 재생 중 video4.mp4가 먼저 잡힘, video4 재생 중 video4-L/video5.mp4가 잡힘 등). 체감 전환은 즉시(하드 컷)에 가까움.
- **경미한 네트워크 낭비**: 일부 mp3/mp4 요청이 `net::ERR_ABORTED`로 실패한 직후 동일 URL이 재요청되어 성공하는 패턴이 여러 번 관측됨(video2.mp3, video4-L.mp3, video4-IN.mp4/mp3, video5*.mp3 등). 재생을 막는 수준은 아니지만 중복 fetch가 있다는 신호.
- 정확한 총 바이트/첫 인터랙션까지의 ms 단위 수치는 이번 조사에서 별도로 계측하지 않음(§9).

## 7. 품질 요소 — 잘한 것 / 거친 것

**잘한 것**
- 20세기폭스 패러디 로고("AI GENERATED MOVIE")가 실제 폭스 로고 카메라무브·서치라이트·금속 질감을 상당히 잘 재현 — 첫 인상 후킹이 강함.
- 포스터(AI EVOLUTION / A-EYE / AI STORY) 3종 모두 실제 영화 포스터 문법(타이포, 카피, 배우 크레딧 라인까지)을 흉내 내 완성도가 높고, "토이스토리" 패러디는 태그라인 유머("THE ALGORITHMS ARE LIVE!")까지 챙김.
- video5-IN 마지막 프레임 → video6-HIDDEN 첫 프레임이 **완전히 동일한 컷으로 이어지는 연속성**(엔드 프레임=다음 스타트 프레임)이 정확히 구현됨 — 히든엔딩을 찾았을 때 "같은 세계가 계속되고 있다"는 느낌을 자연스럽게 줌.
- 글로우 힌트가 "본 적 없는 방향"으로 동적으로 이동하는 로직(방문 플래그 기반)이 사용자를 은근히 안 가본 분기로 유도 — 절제된 넛지.
- 다큐(-IN) 구간에 자체 타임라인+점프가 있어 긴 러닝타임(최대 2:29)에도 지루함을 우회할 장치를 마련해둠. 스킵 버튼도 본편/연결샷엔 허용, 몰입 구간(다큐·엔딩)엔 차단해 리듬을 관리.
- 전체 플레이스루 동안 JS 콘솔 에러가 사실상 0건 — 안정적.

**거친 것**
- 자막이 2~3줄로 길어지면 하단 Skip 버튼과 시각적으로 겹치거나(데스크톱), 화면 밖으로 잘려나간다(모바일 확인, `mobile-timeline-jump.png`).
- "AI STORY" 포스터의 태그라인에 오타 존재: **"ALGORTHHMS"**(ALGORITHMS 오타)가 그대로 배포됨.
- video3-L/video3-R가 데이터에는 정의돼 있지만 `available:false`라 실제로는 죽은 분기 — 사용자에게는 안 보이니 UX 사고는 아니지만, 좌측 스토리 라인이 미완성 상태로 남아있다는 뜻.
- 인트로 로고 씬이 세로 화면에서 가로 타이포가 잘려 "ENERATED / OVIE"처럼 읽히는 등 모바일 크롭 미대응.
- 모바일에서 화살표·자막이 모바일 전용 설정값(40px/13px)이 아니라 데스크톱 값으로 렌더링되는 것으로 보이는 정황(§5) — 반응형 분기 로직 확인 필요.
- 다큐(-IN) 종료 시점에 "up" 버튼이 재등장하는 동작을 관측했는데 목적(재탐색/루프?)이 UI상 명확히 설명되지 않음.

## 8. 재현 체크리스트

1. **그래프 데이터 우선 확보**: `/api/video-flow`(노드·버튼·네비게이션·available 플래그)와 `/api/app-settings`(디자인 토큰, `videoTiming`=버튼 등장까지 "끝나기 전 초", `videoSkip`, `videoGlow`, `subtitles`(KO/EN 전문+스타일), `timeline`, `hiddenLinks`, `bgm`)를 JSON으로 그대로 이식하면 로직의 8할은 재현됨.
2. **듀얼 비디오 엘리먼트 크로스페이드**: `video-player`(활성, z-index 1)와 `video-player-inactive`(이전 프레임 유지, z-index 0) 두 개를 동시에 두고 전환 — 화면 끊김 없는 컷 전환의 핵심.
3. **버튼 등장 타이밍**은 영상 "시작"이 아니라 **"끝나기 N초 전"**(`videoTiming`)에 나타나도록 구현(기본 8초, 다큐류는 1초, 짧은 연결샷은 3초).
4. **글로우는 단일 지시등**: 기본 방향(glow1)에서 시작해, 방문 플래그 조건이 만족되면 다른 방향(glow2)으로 갈아탄다(동시에 두 방향이 빛나지 않음). CSS는 `opacity` keyframe(0%,100%=min / 50%=max, 1.5s infinite)로 구현.
5. **available:false인 목적지로 가는 버튼은 아예 렌더링하지 않는다**(존재하되 숨김이 아니라 DOM 자체에서 제외) — 미완성 콘텐츠 방어 패턴으로 채택.
6. **오디오는 영상과 분리**: `<video muted>` + 별도 `<audio>`(내레이션 mp3, 노드별) + 별도 `<audio data-testid="audio-bgm">`(BGM, 섹션별 on/off·시간 동기화 재개) 3중 트랙 구조.
7. **타임라인 UI**는 진행바+포인트 배열(시각, 제목 KO/EN, 첫 포인트만 호버프리뷰)로 구성하고 클릭 시 `video.currentTime`을 즉시 해당 초로 세팅.
8. **히든 엔딩**은 특정 비디오의 특정 시간 구간에만 존재하는 **투명 좌표 히트박스**(퍼센트 좌표+크기, `previewEnabled:false`로 시각 힌트 없음)로 구현하고, 클릭 시 다음 노드로 라우팅. 씬 안의 소품(쓰레기통)과 좌표를 맞춰 "우연히 찾아지는" 느낌을 의도적으로 설계.
9. **엔딩 화면**: `isEnding` 노드는 끝나면 검은 화면 + "다시보기" 알약 버튼 + 저작자 링크만 남긴다.
10. 실제 모바일 기기/에뮬레이터로 반응형 분기(디자인 토큰의 `mobile` 값이 실제로 적용되는지)를 별도 검증할 것 — 이번 조사에서 의심 정황 있음(§5).

## 9. 미탐색·실패

- **video3-L / video3-R**: API에 존재하나 `available:false`이며 UI에 진입 버튼이 렌더링되지 않아 실제 진입 불가. 우회 진입(직접 URL 파라미터 등)은 시도하지 않음 — 공개 UI 흐름 밖의 접근이라 범위를 벗어난다고 판단.
- **영어(EN) 전환 시 더빙 mp3 실제 교체 여부**: 자막 데이터셋은 KO/EN 완전 분리를 확인했으나, 언어 토글을 직접 클릭해 오디오 경로가 바뀌는지는 검증하지 못함(브라우저 세션 충돌로 시간 소진).
- **정확한 성능 수치**(첫 인터랙션까지 총 바이트, ms 단위 첫 영상 재생 시간)는 정성적 관측만 하고 별도로 계측하지 못함.
- **관리자/설정 진입점 내부**: `/admin`이 401 로그인 벽 뒤에 있음을 확인했을 뿐 내부 화면은 보지 못함(로그인 시도 금지 지침 준수).
- **히든엔딩 "비밀번호" 스텝**: 이번 실측 흐름에는 없었음. 사용자가 전해들은 설명(쓰레기통→비밀번호→히든엔딩)과 실측(쓰레기통 클릭→즉시 히든엔딩)이 어긋나는데, 원인은 확인하지 못함(버전 차이 추정).
- video3-IN/video4-IN 종료 시 재등장하는 "up" 버튼의 정확한 목적(루프/재탐색)은 클릭까지 해보지 않아 미확인.
- 데스크톱 화면에서 언어 토글·설정 진입점의 정확한 모양은 아이콘까지 근접 촬영하지 못함(공유 브라우저 세션 충돌로 시간 배분).

## DYW와의 경험 차이 (아는 범위)

design-your-world(DYW)는 발표/프레젠테이션용으로 **Quick Jump 드롭다운**(전체 노드를 목록으로 즉시 스킵), 핫스팟형 선택("Which door will you open?" 같은 명시적 분기 버튼)과 좌측 사이드 메뉴(Monitor/Trophy/Notebook 등 전시 콘텐츠 내비게이션)를 전면에 노출해 "발표자가 원하는 지점으로 즉시 점프"하는 실용성에 방점이 있어 보였다(같은 세션에서 우연히 관측된 범위 한정).

반면 aimovie는 화살표(방향키형 분기)·다큐 내 미니 타임라인·투명 히트박스 히든엔딩처럼 **탐험과 발견의 서사**를 만드는 쪽으로 설계돼 있다. Quick Jump 같은 "치트키"가 없고, 글로우 힌트만 은근히 다음 경로를 제안하며, 히든엔딩은 좌표 하나를 외워서 찾는 게 아니라 장면 속 소품(쓰러진 쓰레기통)을 알아채야 하는 방식이다. DYW가 "발표자가 빠르게 원하는 곳으로"라면, aimovie는 "관객이 영화처럼 순서대로 보되, 두 번째 볼 땐 다른 길로/숨은 걸 찾아보라"는 재관람 유도형 구조다.
