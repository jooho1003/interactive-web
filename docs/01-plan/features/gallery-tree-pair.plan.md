# 꽃나무 두 그루 · Plan/Design

2026-10-05 · bkit Plan → Design → Do → Check → Act

문제: 사용자가 나무가 건물을 뚫고 두 그루가 같은 형태라고 확인했다. 외부 반복4그루를 두 개의 독립적인 형태/식재 위치로 바꾼다. 오른쪽 마당의 앞 나무는 낮고 넓은 굽은 줄기, 뒤 나무는 가늘고 수직으로 자라는 형태다. 건물과 관람 경로는 그대로다.

참고: docs00/10/11/14, LAB README/QA, 이전 꽃나무 분석, 사용자 사진. 사진의 검은 줄기·분홍 작은 꽃을 재사용하되 동일 실루엣 반복/좌우 반전은 사용하지 않는다. 외부 상호작용 레퍼런스는 해당 없음(위치/장식 교체). 걷는 건물은 실제3D, 장식 나무는 기존2.5D를 유지한다.

1. 서로 다른 두 투명 에셋 → 실제 실루엣/뿌리/알파 여백 확인.
2. 외부 화단도 두 개로 정리하고 위치 이동 → 나무 quad 전체를 외벽 최대x보다 최소.4m 밖에 배치. 각 설정/이미지 크기 변경마다 transform된 네 꼭짓점의 minX를 계산해 필요한 만큼 바깥으로 밀어낸다. 가지를 벽 경계에서 잘라 숨기는 방식에 의존하지 않는다.
3. 기본/최대 크기·폭·방향·뿌리 기준·안쪽 위치에서 실제 quad minX 검사, 입장 중/홀/외관 캡처와 전체 회귀 확인.

레이어 계약: 앞 나무 courtyard-trees와 뒤 나무 courtyard-tree-back을 독립적으로 조절한다. 각13파라미터: 보이기/opacity/image/height/spread/baseX/baseY/brightness/tint/yaw/x/z/화단색. 화단은 해당 나무의 실제 뿌리 좌표를 따른다. 안전 외벽 경계/접지 높이/alpha 기준은 fixed에 이유를 적는다. lint/probe/실제 renderer 및 안전 좌표 검증은 QA에 기록한다. 이미지/프롬프트는 중앙 prompts에 기록하고 보관함을 재빌드한다.


최종 배치: 앞(12.3,0), 높이4.7m; 뒤(12.5,-7.8), 높이6.1m. 원래 외부4그루/화단은 두 그루/동적 화단으로 정리했다. 구현/Check/Act 완료:11레이어107파라미터 lint0, 세 화면107/107 probe 및 renderer/안전 검사 PASS. 결과는 [분석](../../03-analysis/gallery-tree-pair.analysis.md)과 앱 QA에 기록했다.


## 추가 위치 조정 · 2026-10-05
요청: 나무 둘이 동시에 보이도록 위치만 약간 다르게 한다. 기존 자료/QA를 재사용하고 새 에셋·카메라 변경은 적용하지 않는다. Plan/Design:굽은 나무(11.8,-2),곧은 나무(13,0)로 x/z 네 기본값만 변경해 줄기와 화단의 화면상 겹침을 줄인다. 레이어/107파라미터/고정 안전 경계는 유지한다. 검증:기본 외관 두 줄기·화단을 직접 확인, 실제 minX≥10.2m, 입장/복귀·107개 probe·앱check/build를 검사한다. 결과는 QA에 남긴다.
