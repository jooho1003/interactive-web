# 04. 제작 가이드 — 컨셉에서 배포까지

강연 워크플로우 + 사이트 분석을 합쳐 **한 편의 인터랙티브 웹을 만드는 표준 절차**로 정리했다. 모노레포(03)가 준비되면 3단계 이후가 "복제 + 관리자 조정"으로 줄어든다.

---

## 0. 시작 전 체크

- [ ] 어느 **패밀리**인가? (A 3D 공간 / B 분기형 비디오 / A' 월드 게임 / D 플랫폼) → 05 카탈로그
- [ ] 베이스 앱이 이미 있으면 **복제**한다. 처음부터 만들지 않는다.
- [ ] 저장해 둔 인스퍼레이션을 한 번 훑는다 (강연자 습관: 프로젝트 시작 때마다).
- [ ] 스토리가 있는가? "왜 이 공간/이 영화인가"가 한 문장으로 나와야 한다.

## 1. 컨셉 & 스타일 프레임

### 1-1. 스타일 프레임 1장
- Flora(또는 노드형 툴)에서 **룩이 확정된 장면 한 장**을 만든다. 이것이 모든 에셋의 기준.
- 이미지 모델 운용 (2026-09 기준):
  1. 룩 탐색은 Midjourney (독특한 디자인 룩)
  2. 확정 룩을 Nano Banana 2 / GPT Image 2로 변형·수정 (프롬프트 하나에 각 2장씩)
  3. GPT 결과가 너무 샤프하거나 노이즈가 있으면 **Nano Banana로 한 번 더 통과**
- 채팅형이 아니라 노드형으로: 오른쪽이 최신, 되돌아갈 때 오른쪽만 본다.

### 1-2. 베리에이션 대량 생산 (필요 시)
- 프롬프트 베리에이션 10개 생성 → 줄바꿈으로 쪼개기 → 배치 노드로 묶기.
- 텍스트 10 × 이미지 10 = 100 베리에이션. 인터랙티브 영화의 "방 안 / 귀신 등장 / 아무 일 없음" 같은 시나리오 분기에 쓴다.

## 2. 에셋 분해 (패밀리 A/A')

### 2-1. 분해 원칙
| 레이어 | 처리 | 예시 |
|---|---|---|
| 메인 캐릭터 | **단독 1장** (그리드에 넣지 않음) | 경찰관, 점프수트 인물 |
| 소품 | 4×4 그리드 시트 → 16장 슬라이스 | 랜턴, 전화, 랩탑, 의자, 책상 |
| 구조물 | 개별 1장씩 | 벽 패널, 폐허 벽, 바닥 타일 |
| 환경 | HDRI/환경 이미지 | `env-image` |

### 2-2. 프랍 시트 프롬프트 (그대로 사용)
```
[스타일 프레임 첨부]
이 이미지에 있는 사람을 제외한 오브젝트들을 4×4 그리드 안에 하나씩 나눠서 넣어줘.
각 칸은 오브젝트 하나, 배경은 단색, 같은 조명과 같은 재질 스타일로.
```
- 결과: 한 장에 16개, 스타일 통일.
- Flora 자동 자르기(또는 `tools/asset-pipeline/slice-grid`)로 16개 파일로.

### 2-2-1. 생성 순서 (영상 3편에서 확인)
캐릭터 먼저 → "이 캐릭터에 어울리는 배경 만들어줘" → "캐릭터 빼줘" → 바닥/왼쪽/뒷면 분할. 배경을 먼저 만들면 캐릭터가 안 붙는다.

### 2-2-2. 게임 UI 킷 프롬프트 (2편)
```
게임 UI를 하나씩 만들지 말고 UI 킷으로 한 장에 만들어줘.
윗줄: 기본 상태 / 둘째 줄: 하이라이트 상태 / 아랫줄: 비활성 상태.
같은 스타일로 STAGE 1~5, SINGLE PLAY, VS PLAY, GAME OVER, READY, START 텍스트 킷도.
```
- 무기·능력 아이콘도 "FULL WEAPON & ABILITY UI SHEET (EXPANDED, ISOLATED)" 한 장 → 슬라이스.
- 인트로 이미지는 "이 배경과 캐릭터로 게임 인트로 만들어줘" → 마음에 드는 것에서 **버튼만 떼서 메뉴로, 배경은 영상으로**.

### 2-2-3. 스테이지 전환 영상
현재 스테이지 이미지(Start) + 다음 스테이지 이미지(End) → "1스테이지에서 2스테이지로 걸어가" → 전환 시 재생. Connect Idea 에디터의 우클릭 Generate Video와 같은 원리.

### 2-3. 3D 변환
- **먼저 3D가 정말 필요한지 본다(2026-10-04).** 인터랙티브 웹의 기본은 3D 모델이 아니라 [14번](14-2.5D-이미지-제작-방식.md)의 **3D 느낌 투명 PNG + CSS 원근 깊이**다(POTATO 검증). 뒷면·옆면 노출, 관절 동작, 공간 이동, 숏폼 재사용이 필요할 때만 아래 실제 3D 경로를 탄다.
- **실제 3D 경로(2026-09-23 채택): Meshy 제작 → Blender 세부 수정·연출 → Three.js 웹 상호작용.** 숏폼과 웹이 같은 Blender 자산 정본을 사용하고, 영상과 경량 GLB를 각각 출력한다. 자산·레이어·검수 정본은 [13번 설계](13-3D-공통-제작-파이프라인-설계.md)다. 아직 제작/런타임 구현 전이다.
- 캐릭터는 팔·다리가 분리된 중립 자세, 소품·구조물은 개별 자산으로 생성한다. 움직일 캐릭터의 극단적인 포즈는 Blender 동작 단계에서 만든다.
- 강연의 Tripo 16장 작업은 원본 참고 이력으로 남긴다. 16개 오브젝트의 개별 생성 작업이며, 한 모델에 16개 시점을 넣는 뜻이 아니다. 실제 병렬 수는 계정 한도와 제작 예산으로 정한다.
- 파일은 안정된 `assetId/revision`으로 연결하고 관리자에는 표시 이름을 쓴다. 새 파일/버전 규칙은 13번을 따른다.
- 배경 전체를 한 모델로 넘기지 않고 캐릭터·소품·벽·바닥으로 나눈다.

### 2-4. 최적화 (업로드 전 필수)
새 제작의 초기 목표는 [13번 §4-4](13-3D-공통-제작-파이프라인-설계.md#4-4-웹-출력과-성능-목표)를 따른다. 아래 명령은 기존 압축 예시이며, 실제 사용 시 로더의 Meshopt/KTX2 decoder 지원과 압축 뒤 동작·재질·클립 검사를 함께 확인한다.

```bash
# tools/asset-pipeline
gltfpack -i in.glb -o out.glb -cc -tc      # 메시 압축 + KTX2 텍스처
```
- 목표: 오브젝트당 ≤ 2 MB, 캐릭터 ≤ 5 MB, 공간 총합 ≤ 30 MB (§5 예산).
- 텍스처 2048 → 1024로 줄여도 웹에서는 대부분 티가 안 난다.

## 3. 영상 제작 (패밀리 B)

### 3-1. 그래프 먼저
- `video-flow` JSON을 먼저 쓴다. 파일이 없어도 `available:false`로 그래프는 동작한다.
- 노드 명명: `video3`, `video3-L`, `video3-IN`, `video3-R` (본선 / 좌 / 진입 / 우). 히든 엔딩은 `-HIDDEN`.
- 플래그 설계: 진입 노드에 `setsFlag`, 본선 노드에 `glowCondition`으로 "이미 봤으면 다음으로 안내".

### 3-2. 컷 생성
- 영화식 체인: **이전 컷의 엔드 프레임 = 다음 컷의 스타트 프레임**. 스타트/엔드 지정은 Kling.
- 캐릭터 시트 + 공간 참조로 "알아서 해줘"는 Seedance. 단, 저작권 캐릭터는 막힌다 → Kling.
- 프롬프트 하나에 Kling 2 + Seedance 2, 골라 쓴다. 100개 만들고 하나 고르는 게 정상이다.
- 캐릭터 일관성이 무너지면: 가우시안 스플랫(또는 3D 턴테이블) 영상을 인풋으로 **video-to-video**.

### 3-3. 인코딩
```bash
ffmpeg -i in.mov -c:v libx264 -crf 23 -preset slow -vf scale=1920:-2 -movflags +faststart -an video3.mp4
ffmpeg -i in.mov -vn -c:a libmp3lame -q:a 4 video3.mp3          # 언어별 더빙 트랙
ffmpeg -ss 00:00:00.5 -i video3.mp4 -frames:v 1 video3_q.png     # 포스터 프레임
```
- 영상은 **무음 mp4 + 언어별 mp3** 분리 (레퍼런스 방식). 더빙만 바꿔 다국어.
- 모바일용 저해상도(`_m1`) 별도.
- 목표: 1080p, ≤ 8 Mbps, 컷당 ≤ 40 MB.

### 3-4. 자막
- `subtitles.<device>.<LANG>.videos.<node>` 배열. `start/end`는 `mm:ss` 또는 `mm:ss.s`.
- 스타일(폰트·크기·위치·그림자)은 관리자에서. 자막 텍스트는 JSON 가져오기로 일괄.

## 4. 바이브 코딩 — 툴 만들기

### 4-0. 순서: 기술 검증 → 레퍼런스 → 디자인
"그리드로 카메라를 연동해서 움직이나 안 움직이나, 여기까지만 딱 하고." 핵심 인터랙션이 되는지 그리드 하나로 먼저 확인한다. 되면 옵션(간격·라이트)을 붙이고, **그 다음에** 레퍼런스를 모으고 에셋을 만든다. 안 되는 기술에 에셋을 만들지 않는다.

### 4-1. 초기 프롬프트 (베이스 앱이 없을 때)
```
[레퍼런스] 첨부 캡처는 구성 참고용이다. 그대로 따라 하지 말고 이런 느낌으로.
[목표] 카메라로 얼굴을 추적하면 창문처럼 들여다보이는 3D 공간 체험 웹.
      카메라가 없으면 마우스로 동작해야 한다.
[관리자] 네가 만드는 모든 기능은 관리자 탭에서 조작 가능해야 한다.
        메뉴를 만들면 그 메뉴의 디자인도 관리자 디자인 탭에서 수정할 수 있게 해라.
        화면에 보이는 텍스트·색·폰트·이미지는 편집 툴바에서 요소를 클릭해
        바로 고칠 수 있어야 한다. 설정 경로를 요소에 바인딩해라.
        데스크톱과 모바일 값을 따로 둔다.
[성능] 웹에서 카메라와 3D가 동시에 돌아야 하므로 가볍게. 로우폴리 GLB 기준.
[첫 기능] GLB 파일을 올릴 수 있는 공간부터. 나머지는 테스트 후 추가한다.
```
- 음성으로 길게 말한다. 상의하듯이. "어느 정도를 원하는지"를 말한다.
- 모노레포가 있으면 이 프롬프트는 `pnpm new portal-space <name>`으로 대체된다.

### 4-2. 기능 증분 프롬프트 (검증된 순서)
| 순서 | 프롬프트 | 결과 |
|---|---|---|
| 1 | 3D 파일을 올릴 수 있는 공간을 만들어줘 | 파일 선택 버튼 |
| 2 | 불편해. 드래그 드롭으로 해줘 | 단일 DnD |
| 3 | 여러 개도 되게 해줘 | 멀티 DnD |
| 4 | 동시에 여러 개 선택해서 크기 조절도 되게 해줘 | 멀티 선택 스케일 |
| 5 | 레이어 패널, 되돌리기(Ctrl+Z/Y), 씬 전체 저장/불러오기 | 에디터 |
| 6 | 조명·안개·글로우를 관리자 슬라이더로 | LightSettings |
| 7 | 공간을 여러 개 만들고 이전/다음으로 이동 | spaces |
| 8 | 우측 상단에 관리자만 보이는 세팅창. 화면 요소를 클릭해 문구·크기·색·이미지를 바로 고치게 | 편집 툴바 |

- 막히면 명령이 아니라 질문: "슬라이더로는 안 된다. 해결책을 네가 제안해. 이미지 교체 기능도 넣어줘."
- 8번은 강연에서 **가장 나중에** 나온 기능이다. 관리자 패널이 이미 다 있는데도 "귀찮아서" 추가됐다 (`02-게임-영화-툴-시연.txt:279`). 기능 부족이 아니라 **탐색 비용** 문제이므로, 툴바에는 화면에 보이는 것만 올린다 (03 §3-3-4).

### 4-3. 툴바 우선 규칙
고치는 순서가 정해져 있다. **툴바 → 관리자 폼 → 프롬프트.** 위에서 막힐 때만 아래로 내려간다.

| 순서 | 수단 | 쓰는 때 | 걸리는 시간 |
|---|---|---|---|
| 1 | **편집 툴바** (03 §3-3) | 화면에 보이는 것 — 문구, 폰트, 색, 이미지, 여백 | 초 |
| 2 | **관리자 폼** (`/admin`) | 화면에 안 보이는 것 — 타이밍, 플래그, 그래프, 자막 트랙, 앱 정보 | 분 |
| 3 | **프롬프트** | 위 둘에 컨트롤 자체가 없을 때 | 시간 |

**클라이언트 손에 있어야 하는 최소 집합은 셋이다 — 멘트 · 글씨 크기 · 대략적 디자인.**
> "관리자가 로그인하면 관리자가 그 **멘트**를 바꿀 수도 있고 이 **글씨 크기**도 바꿀 수도 있고 **대략적인 디자인**을 여기서 바꿀 수 있게 해놨습니다" (`docs/transcripts/03-OSF-클라이언트-시연.txt:22`)

이 셋이 툴바 MVP 범위다. 나머지는 있으면 좋은 것.

- 3으로 갈 때는 값을 고치라고 하지 말고 **컨트롤을 추가하라고** 시킨다. 값을 코드에 박게 두지 않는다.
- 새 값이 생기면 `config-schema`에 먼저 (03 §7 규칙 1). 그 다음 `<Editable path=…>`로 요소에 바인딩한다 (03 §7 규칙 7).
- **툴바에서 고쳤는데 출처 배지가 `[오버라이드]`면 빚을 진 것이다.** 한 번뿐이면 넘어가고, 같은 걸 또 고치게 되면 관리자 오버라이드 탭에서 "스키마로 승격"을 눌러 갚는다 (03 §3-3-5).
- **이미지 안에 텍스트를 굽지 않는다.** 툴바로 고칠 수 없게 된다. 포스터의 오타를 고치려고 이미지를 다시 만들게 된다 (aimovie의 `ALGORTHHMS` 사고, 08 §5).
- **클라이언트 디자인 재현**: 시안을 그대로 프롬프트에 넣으면 "비슷한데 다르게" 나온다. "슬라이드 컨트롤러 만들어 달라" → 직접 맞춰서 똑같이 만든다 (OSF 사례).
- **자막·오버레이를 영상에 굽지 않는다.** 웹 인코딩에서 뭉개진다. 타이밍 자막 기능으로.
- **완성 기준**: 앱 안에서 영상·GLB 업로드와 분기 편집까지 되면 바이브 코딩 없이 다음 작품을 만들 수 있다. 그때가 툴 완성이다.

### 4-3-1. 이스터에그 체인
비밀 버튼 → 숨은 장소 → 비밀번호 → 히든 엔딩. **이 비밀번호가 다음 작품의 암호**가 된다. 관리자 앱 정보 탭의 `secretCode` / `nextWorkHint`에 기록해 작품 간 연속성을 유지한다.

### 4-3-2. 일단 실행
완벽한 기획 후 완성보다 빠른 이터레이션으로 만들면서 변형한다. 오프-액시스 → 사이파이 갤러리 → 매트릭스 오마주 → 게임은 계획이 아니라 변형의 결과였다. 플랜은 노드 3~4개까지만 잡고 시작한다.

### 4-4. 병렬 작업
- 프롬프트 던지고 기다리는 동안 다른 앱 탭으로. 3~4개 동시.
- 클라우드(Replit)면 핸드폰에서도 진행 가능. 이동 중엔 음성 입력.
